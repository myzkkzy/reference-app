## 更新単位と編集履歴

以下は[ADR-006](architecture-decisions/2026-09-26-ADR-006-session-edit-history.md)の提案であり、基本編集のUndo／Redoは2026-10-03に要件へ反映済みである。組合せ境界の具体化とADR採用判断は残る。

| 操作                               | 確定時の更新単位                                                    | 取り消し時に戻す範囲                         |
| ---------------------------------- | ------------------------------------------------------------------- | -------------------------------------------- |
| 画像・メモの移動、画像の回転・拡縮 | 選択前面化と一つのドラッグ開始から終了までを1操作とする                       | 操作開始前の配置                             |
| グループの一括移動                 | 所属する全画像・メモの位置を1操作で変更                             | 同じ全要素の位置                             |
| グループへの所属変更・除外・解除   | 関連要素の所属変更を一括確定                                        | 旧所属。座標・重なり順は維持                 |
| 画像削除                           | ボードから除外し、取消用に同じ画像データと配置・所属を保持          | 画像・配置・所属・重なり順。空グループは維持 |
| メモ本文編集 | 入力中は文章内履歴。編集終了または手動・定期保存の対象確定時に入力済み文章を確定。IME変換中部分は除外 | 編集取消は直近の確定文章へ戻す。保存対象として確定するたびにボードUndoを区切るが文章内Undoは保持する。書込失敗でも確定と区切りを戻さない |

ボードの保存対象、編集中の一時表示・選択、編集履歴を別の状態として扱う。パン・ズーム、重なり順を変えない選択状態の変更、保存処理自体はボード編集履歴へ積まない。選択に伴う永続的な前面化は編集として保存・Undo対象にする。履歴は保存成功後も開いている間維持し、閉じると破棄する。削除した画像データは、開いている間に取り消すために必要な範囲で保持する。画像データの実体と配置情報は分離し、ZIPには現在のボードに必要な画像だけを含める案とする。Redoを提供し、新しい編集の確定でRedoを破棄する。保存・パン・ズーム・純粋な選択変更だけではRedoを破棄しない。履歴上限はUndo・Redoの合計1～1,000操作（既定100）で、同じWindowsユーザーの全プロジェクトに共通するアプリ設定から変更する。変更は次回の新規作成・オープン・再オープンに適用し、現在の履歴は変えない。上限超過は最古の操作から破棄し、不要になった画像参照を解放する。文章内Undoはこの上限に含めない。設定保存はDES-007に従う。ドラッグ中の自動保存は次節に従う。

ボード・表示中心と倍率の確定はboardRevision、設定変更はsettingsRevisionを進める。成功番号も二系統で管理し、設定だけの保存でボードを保存済みにしない。Rustは直前成功スナップショットと画像参照を保持し、設定保存ではそこへ新設定だけを合成する。履歴・直前成功内容・保存処理・候補読込が参照する画像を削除操作だけで解放しない。保存の正本は[DES-009](project-persistence.md)。

メモは手動・定期保存時に確定済み入力をボードへ確定し、そのまま入力を続けられる。IME変換中部分は変換開始直前の確定入力から分離して保持する。編集取消の基点は保存対象として確定した文章へ進め、書込失敗でもその文章を未保存で保持する。未確定入力は保存済み表示とは別に示す。終了・切替時の入力解消は[保存ゲート](project-persistence.md#終了切替の保存ゲート)に従う。

### ドラッグ中の自動保存

2026-09-27の本人選択に基づき、自動保存は確定済みのボード状態を対象とする。画像・メモの移動、画像の回転・拡縮、グループ移動に適用する。ドラッグ途中の配置は表示用の一時状態として保持し、確定済みの配置と更新番号を書き換えない。

- 30秒の固定周期を維持する。保存時刻に確定済みの未保存変更があれば、その状態と更新番号を固定して保存する。ドラッグ中の対象は操作開始前の確定済み配置を含める。確定済みの未保存変更がなければ保存を省略する。
- ドラッグ終了時に変更があれば、最終配置を1操作として確定し、更新番号を進める。グループ移動は全対象を一括で確定する。中止は位置・前面化・付随枠変更を開始前へ戻す。無移動クリックでも前面化を確定し、重なり順が変わった場合だけ履歴を追加する。位置・順序・枠がすべて同値なら番号・履歴を追加しない。
- 保存対象を固定した後にドラッグが終了しても、進行中の保存対象は変更しない。確定した結果は未保存として表示し、次の固定周期または手動保存で保存する。ドラッグ終了だけを理由に追加の自動保存は開始しない。
- 保存処理中に次の固定時刻を迎えた場合は、REQ-012に従って保存を同時実行せず、保留した要求を1回に集約する。先行保存の成功後に確定済みの未保存変更があれば、その時点の最新状態を固定して続けて保存する。まだドラッグ中なら途中配置を除き、終了済みなら確定後の配置を含める。確定済みの未保存変更がなければ追加保存を省略する。
- 保存の成功表示は保存対象の更新番号に対応させ、ドラッグ確定後の変更まで保存済みにしない。失敗時は保存成功番号を進めず、REQ-015・016の失敗表示・内容保護・再試行方針に従う。

判断理由は[ADR-006](architecture-decisions/2026-09-26-ADR-006-session-edit-history.md#決定と理由)に記録する。手動保存も確定済み内容を対象とし、ドラッグ終了を待たず要求を受け付け、操作を継続する。対象の途中配置を含めず、ドラッグ終了後の変更は次の保存対象となる。同じ保存先で先行保存中の場合はDES-009の直列化に従う。メモ本文の保存境界は前節とDES-009に従う。

## 保存・復元と異常時の扱い

保存対象の定義は[DES-004](data-design/board-state.md#保存対象と境界)を正本とする。読込は参照と内容の整合を確認してからボード状態を切り替え、破損時には現在のボードと保存ファイルを変更しない。形式識別・バージョン、詳細スキーマは[DES-008](data-design/project-file.md)、保存・読込・復旧の契約は[DES-009](project-persistence.md)を参照する。

| 事象                               | 保護・回復の方針                                                             |
| ---------------------------------- | ---------------------------------------------------------------------------- |
| 保存中の編集・取り消し             | 保存対象番号と後続変更を分け、新しい状態を古い保存結果で置き換えない         |
| 読込中の不正な所属・画像参照・座標 | 新しい内容へ切り替えず、対象と理由を通知する                                 |
| グループ移動・所属変更の中断       | 関連要素を部分的に確定した状態を保存対象にしない                             |
| アプリ強制終了                     | 最後の保存成功内容まで復元する。セッション履歴と未保存変更の復元は保証しない |

## 検証観点

- 画像・メモの所属変更、グループ解除・移動、空グループ化・再利用・保存再開で、位置・相対配置・重なり順が保たれるか。
- 画像削除の取り消しで、元ファイルに触れず画像データ・配置・所属を復元できるか。拡張された基本編集の取り消し範囲は要件反映後に評価する。
- 保存中に編集・取り消しを行っても、保存成功と未保存を区別でき、古い保存結果が新しい状態を置き換えないか。
- ドラッグ中の定期時刻に、確定済みの未保存変更がある場合は開始前の配置を保存し、ない場合は省略するか。長いドラッグでも固定周期と途中配置の除外を維持するか。
- 保存対象の固定後にドラッグが終了した場合、結果が未保存として残るか。保存中に次周期を迎えた場合の追加保存が、その開始時点で確定済みの最新状態だけを含むか。
- ドラッグの中止・無変更終了で更新番号や履歴を増やさず、グループ移動の一部だけが保存されないか。
- 多数画像の履歴・削除取消に必要な資源量を確認する。具体的なケース、環境、手順、実測は実装・検証担当へ引き継ぐ。

## 選択・枠・入力の確定方針

2026-10-03、セッション内の決定事項の反映指示に基づく要約。元の各対話日時は補作しない。要件全体の合意・ADR採用・試験合格とは別に扱う。

- 画像・メモの選択で最前面へ移し、選択解除後も重なり順を維持する。最前面・最背面の操作を設ける。複数選択とグループヘッダー選択では対象間の相対順を保って全対象を前面化する。
- 選択と続く移動は一つのUndo操作にする。ポインターを離したとき位置・前面化を同時確定する。途中保存は両方とも開始前。取消は両方戻す。Undo・Redoと最背面操作後も選択は維持し、選択状態に反応して再前面化しない。
- グループ枠の手動変更・「中身に合わせる」はUndo対象。枠は通常維持し、必要時だけ拡大する。全グループの枠を保存し、枠変更で所属要素を拡縮・移動しない。
- メモは可変幅、全文に追従する自動高さ、折返しと明示改行、10,000文字上限とする。保存対象確定前がA、途中保存がAB、編集終了がABCならボードUndoはAB、Aの順に戻す。保存失敗でもABの確定境界を保持する。
- 画像倍率は1～1600%、ボード倍率の最大は1600%、最小は全体を収める値。固定用紙境界は設けない。座標上限・倍率・数値精度はDES-004の契約に従う。ドラッグ中のAltによるスナップ一時解除は確定とし、DES-006に従う。本文Enterは改行、メモ完了・取消の専用キーは設けない。他の未選定ショートカットは引き続き候補とする。

## メモ編集の入力契約

2026-10-05、セッション計画の実行指示を反映。編集期間は開始から完了／取消まで。本文確定境界と文章内Undo履歴を分ける。

- 編集中のUndo／Redoは文章内履歴だけを使い、同じ編集期間の途中保存より前へ戻れる。空になってもボード履歴へ切り替えない。ボードのUndo／Redo部品は本文編集終了まで無効にし、理由を表示する。
- ボード履歴は本文の直近確定値→新確定値を1操作にする。文章内Undoで途中保存以前へ戻した値を次に確定する場合も、直近確定値との差分として記録する。確定と書込成功を分ける。
- 保存ボタンは確定して編集継続。メモ外のボード・別要素クリックは本文確定→編集終了→クリック先操作の順。別アプリへ切り替えただけでは終了しない。
- IME中のメモ外クリックはボード操作を実行・予約せず、編集を終了しない。入力要素への変換イベントは観測し、終了後に再操作を求める。Enterは改行。完了／取消専用キーは設けず画面部品で操作する。
- 本文をUnicode 17.0のUAX #29既定の拡張書記素クラスタで計数する。入力時にCRLF／CRをLFへ揃え、LFを1文字とする。結合文字・ZWJ家族絵文字はクラスタ単位。保存読込双方で同じ規則を使い、WebViewのUnicode版に計数を委ねない。その他のUnicode正規化はしない。
- 10,000文字を超える貼付けは全体を拒否し、本文・選択範囲・文章内履歴を保持して通知。IME確定で超過なら今回の変換全体を拒否し、開始前の本文・選択範囲へ戻し通知。変換中の値を保存・ボード履歴へ入れない。
- 新規メモは本文未確定なら取消で作成を破棄し履歴なし。空本文も完了／保存対象確定で作成可能。一度確定した後の取消は直近確定本文へ戻しメモを残す。保存失敗でも同じ。編集取消では直近確定済み本文との差分履歴を追加しない。
- 文字サイズ変更と幅変更は本文編集終了後に操作可能にし、本文・幅・サイズ・必要な枠拡大を同じボード操作で確定する。

計数根拠：[UAX #29 Unicode 17.0版](https://www.unicode.org/reports/tr29/tr29-47.html)（2026-10-05確認）。textareaの標準Undoにだけ依存せず文章内履歴をモデル側で保持する提案。IMEイベント／選択復元の成立は検証担当へ渡す。
