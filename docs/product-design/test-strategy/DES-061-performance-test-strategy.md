## 検証目的と主要リスク

利用者の入力に応じた実表示変化、対象細部の最終精細さ、俯瞰と内容復元・操作可能化までの時間を実アプリで確認する。機能・通信・資源の合格から時間基準の達成を推定せず、同じ固定条件の各試行を始点・終点の証拠へ結び付ける。

| 主要リスク | 本テーマの検証判断 |
| --- | --- |
| 軽いダミー画像・不足負荷・任意操作で見かけの合格になる | 既定負荷を維持し、固定画像・ボード・具体操作の未決を正式判定の前提にする |
| accepted・通知・デコード・仮表示を測定終点にする | 入力・実画面・対象解像度・操作可能を観測し、内部段階と受入の終点を区別する |
| 自動だけを測る、保存待機を保存中とする、保存停止ダブルで時間を証明する | 自動と手動、パンとズームを別系列とし、実保存との重なりを証明する |
| 平均値や良い3回だけを選び、未決の計測誤差で閾値を緩める | 各系列の3回すべてを判定し、無効・条件外・証拠不足を別に記録する |

## 品質評価の前提

旧DES-013の製品評価条件を、本テーマの判定方針として継承する。評価PCはCore i5-1235U、16GB、内蔵GPU、SSD、フルHDノート、Windows 11。元画像は全500枚・全数1920×1080、JPEG350・PNG100・WebP20・GIF10・TIFF10・BMP10とし、写真・イラスト相当を含む同じ固定群を反復する。単色ダミー・同一画像の大量複製で代用しない。500枚は登録上限ではない。

| 評価系列 | 維持する受入値と判定方針 |
| --- | --- |
| 通常のパン／ズーム反応、対象細部 | 入力から実表示変化開始まで100ms以内、ズーム停止から対象の最終精細さまで1秒以内 |
| 自動／手動保存中のパン／ズーム反応、対象細部 | 実保存中の入力から実表示変化開始まで500ms以内、ズーム停止から対象の最終精細さまで2秒以内。保存種別を別に判定する |
| 保存済み500枚の再開 | 開く操作から俯瞰・保存内容の復元・操作可能の全成立まで5秒以内 |
| ローカル500枚初回取込 | 空ボードへ元ファイルを渡してから全500画像の実表示・操作可能まで30秒以内 |

境界を含み、各系列の3回すべてが基準内であることを維持する。パンとズームは各3回、自動と手動の保存中系列も分離する。再開・初回取込は各試行前にアプリを再起動し、再起動時間を計測へ含めない。OS再起動やキャッシュ消去という新たな必須条件は追加しない。

詳細な開始状態・始点終点・除外時間は[DES-053の共通仕様](../test-design/DES-053-performance-test-design.md#共通のデータ仕様環境要件手順)を参照する。細部は対象画像の表示範囲に一時低解像度や未描画部分が残らず、その倍率の最終精細さへ達することとする。画面内の全画像完了を追加条件にせず、再開の最初の画像や初回取込の自動保存完了を終点へ置き換えない。ローカル取込へブラウザURL取得時間を混ぜない。

## 確認層と分担

| 確認層・目的 | 本テーマでの適用判断 |
| --- | --- |
| 実機E2Eの製品時間受入 | 実画像処理・実保存・固定WebView2／Canvas／WebGLを通し、実画面と内部段階を関連付けて判定する。対象ビルド・依存版・PC・負荷を固定する |
| Unit・結合による原因切分け | 時計・配送・保存段階・画像取得を制御する診断は、ブロック箇所や負荷の寄与を確認する目的に限る。その所要時間を製品受入へ使わない |
| 機能・整合性・資源の確認 | 各主テーマの証拠を参照し、保存中操作継続や固定後編集の未保存保持、解像度の正しさが成立する条件で時間を測る |

状態固定、Worker受渡し・JSON化／解析、Tauriのコピー、PNG受信・デコード・描画が反応と資源へ与える影響は段階別に切り分ける。非同期APIやバイナリ形式を採用したことだけで画面非ブロック・ゼロコピー・性能達成としない。

## 網羅方針

通常、自動保存中、手動保存中を別の負荷状態とする。反応ではパン・ズームを別系列、細部では指定対象と最終精細さを確認する。再開は俯瞰・配置・グループ・メモの復元・操作可能、初回取込は空ボードへの一括handoff・全画像表示・操作可能を含む。

通常と保存中の評価ボードは同じ固定状態を使い、各試行を所定開始状態へ戻す。保存中は実処理との重なりを証明し、待機・失敗・ブロックだけのキューを保存中としない。計測中に保存が完了した区間の分類と具体的な重ね方はU4の確定時に照合し、現段階で補作しない。

## 観測と制御の方針

入力イベント、要求受付、スナップショット固定、DB生成、ZIP完了、置換・復旧更新・complete、候補検証・採用、PNG受信・デコード、実描画と操作可能化を関連付ける。request・session・asset・snapshot・transaction、保存trigger、両現在／成功番号を証拠へ残す。保存中にパン・ズーム・編集を続けても、古い成功番号で後続編集を保存済みに進めないことを機能・整合性の主判定へ接続する。

時間差は既定の始点・終点で判定する。時計・分解能・時計間同期、画面変化・最終精細さ・操作可能の測定方法、実保存との重なりの検出はU4として未決を維持する。観測負荷と測定誤差の扱いを再レビューし、閾値緩和や架空のフックで補わない。診断用の段階停止と実負荷測定は別の証拠にする。

## 未決事項と引継ぎ

固定画像情報U1、ボード状態U2、具体操作U3、測定法と保存中／細部検出U4は、[DES-053の未決表](../test-design/DES-053-performance-test-design.md#レビュー引継ぎ)を唯一の詳細管理元として維持する。本書はその判定保留を適用し、任意の距離・倍率・対象・測定法を選んで未決を解消しない。設計・検証担当が既定条件と照合して固定し、要件担当が必要な条件合意・上流反映を確認してから影響範囲を再レビューする。

具体ビルド・依存版、評価機、実画像・保存ファイル、観測コード・機器の未作成は後続準備であり、U1～U4の判断待ちとは分ける。既定負荷と各3回全回の方針・ケースは具体化できるが、未決に依存する完全受入判定・引継ぎ可能判断を保留する。未決のまま行う予備検討を正式受入と分け、実行・製品結果は検証担当へ引き継ぐ。
