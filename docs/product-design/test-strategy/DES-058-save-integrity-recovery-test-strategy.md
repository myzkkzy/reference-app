## 検証目的と主要リスク

最後に保存成功した内容を、クラッシュ・強制終了後にも復元できることを優先する。完了前の新内容、成功内容、編集中の追加入力を別状態として扱う。DBコミット・正常なZIP・画面通知だけでは物理成功を判断せず、本ファイル、必要な復旧用処理、完了記録の検証・同期を照合する。

| 主要リスク | 本テーマの検証判断 |
| --- | --- |
| 読める新ZIPや通知から保存成功を誤認する | 保存段階・現物・完了記録を結び、成功前後と通知前後を別に確認する |
| 置換APIの失敗でもファイルの所在が変化し、直前成功内容を失う | API結果と実ファイルの照合を独立させ、退避の完全性と再試行可否を確認する |
| 中断分完了が追加入力を巻き戻す、元失敗要求を成功へ変える | reconcileとfollowupの対象・順序・更新番号を分ける |
| 整理・キャッシュ解放でUndo・保存・候補の画像や唯一の正常コピーを消す | 保持元ごとの所有を確認し、再生成可能なキャッシュと画像実体・復旧資料を区別する |

保証対象は最後の保存成功内容までとする。未保存変更・編集履歴の復元、停電・媒体故障は既存保証へ追加しない。初回成功前に旧成功内容がない状態は既存保存と分ける。

## 確認層と分担

| 確認層 | 確認する境界・証拠 | この層を使う理由 |
| --- | --- | --- |
| Unit | 保存状態、世代連鎖、更新番号、参照所有、再試行の分岐。I/O・通知・時計の結果を制御した前後状態 | 記録不整合、旧／新現物、複数保持元を決定的に確認する |
| 結合 | Windowsの実SQLite・PNG・ZIP、ファイル同期・置換・ロック。実ファイルの所在・完全性・ハッシュと段階記録 | 実APIの部分失敗と物理コピー保護はモデルだけでは成立を判断できない |
| E2E・実機 | 異常終了・再起動、復旧候補の提示・選択、保存中変更、復旧後の別名保存までの保護 | 利用者が復元可能な内容に到達でき、表示・番号・保存内容が一致することを確認する |

旧DES-013の先行成立確認は、DB外PNG照合、置換前後の異常終了、容量不足、排他、外部変更、明示再試行、復旧後別名保存という境界を優先する判断として継承する。大容量ZIP64・DB防御の方式成立は容量・安全読込テーマへ接続する。

## 網羅方針

- 保存状態は、保存未開始の編集中、complete前の処理中、complete同期後の通知前、成功後の整理中を分ける。保存未開始では要求・待機・実処理がないことを証明し、保存途中の停止点やpreviousの前提を適用しない。
- 既存保存の全対象永続化段階を、ボード／設定保存、復旧保持有効／無効で確認する。初回の旧なし状態、設定だけ／表示位置だけの保存は独立して扱う。
- I/O障害は置換前と以降、短い書込、同期失敗、容量不足、アクセス拒否を区別する。再試行は旧／新現物、照合競合、中断分完了後の追加入力、後続保存、再試行中再障害を含む。
- 記録は型・帰属・完全性・ハッシュ連鎖を、外部変更は置換直前・直後・再試行前を確認する。時刻だけで世代・成功を選ばない。
- 画像実体は現在ボード、Undo、Redo、直前成功基準、実行中保存、候補の各保持元を独立させる。未完了・帰属不明・他処理所有・復旧後別名保存前のコピーを整理対象へ混ぜない。

具体的な停止点と保護内容の比較表はDES-050で管理する。上記の網羅軸から条件を抽出し、同本文の根拠→条件→ケースの対応で受入行を確認する。

## 観測と制御の方針

保存固定対象、両現在／成功番号、request・session・transaction、段階到達、実ファイルの所在・サイズ・ハッシュ・検証結果を関連付ける。復元した全保存項目とPNG集合を照合し、再開後の番号だけで旧セッションの保存成功を推定しない。

強制終了は観測した状態・段階で制御し、正常終了保存や追加の後片付けを制御器が代行しない。通知だけの欠落は要求照会による元結果の回収へ接続し、実保存ブロック・中断保持を示す証拠がある行と分離する。失敗通知、書込停止、実現物はそれぞれ観測する。

段階到達・I/O失敗・所有を制御する口は後続実装へ必要能力として渡す。観測不能なら当該行の再現方法を製品設計へ返す。保護した正常コピーと未完了記録は、終端・所有・証拠回収を確認してから扱う。

## 未決事項と引継ぎ

変更後REQの合意レビューと関連ADRの採否は上流担当の判断を維持する。保護・復元の既定契約は具体化済みであり、実APIの制御・観測ができない場合は該当範囲の再現方法を再確認する。具体ビルド、正常・変異資料、容量不足・ACL条件、観測コードが未作成であることは後続準備として扱う。

実装担当へ段階停止・I/O結果・通知・固定対象・所有の観測能力を、検証担当へ原本台帳・独立コピー・停止点の証拠と再起動比較を引き継ぐ。具体的な資料・手順・必要証拠は[DES-050の共通仕様](../test-design/DES-050-save-integrity-recovery-test-design.md#共通のデータ仕様環境要件手順)と[レビュー・引継ぎ](../test-design/DES-050-save-integrity-recovery-test-design.md#レビュー引継ぎ)を正本とする。
