## 対象範囲と検証目的

保存要求の受付から内容固定、実保存成功、状態表示、終了・切替・再開までの機能フローを確認する。プロジェクト設定とPC設定、未保存編集と最後の保存基準、読込した原本と端末で調整した現在状態、ファイル所有を識別し、続きの作業を保護する。

製品受入では保存属性、固定周期、設定の適用範囲、手動保存、状態表示、失敗後の操作、未保存保護、原本非依存・別PC移送、フォント調整、排他・再試行、作業先を確認する。DESの不変snapshot、二系統の番号、操作ゲート、候補採用・所有移管の技術契約は根拠を分ける。受付だけを実保存成功として評価しない。

本テーマは操作・キュー・設定分離・再開調整の管理元である。保存各段階の障害注入、強制終了後の保証、唯一正常内容と画像実体の保護は保存整合性テーマ、型・通知・識別寿命はIPCテーマ、安全読込・容量は資源テーマへ接続する。

## 主要リスクと優先順位

| 主要リスク | 優先理由・確認する保護 |
| --- | --- |
| 古い成功や受付を、最新編集の保存成功と扱う | 編集・要求・固定・成功・通知の順序を分け、最低更新番号、保存kind、後続編集、未確定入力を照合する |
| 設定だけの保存に未保存編集やフォント調整を混入させる | 保存基準と現在状態、board/viewとsettingsの系統を分け、実保存項目と現在編集の双方を保持する |
| 終了・切替の取消後に遅い結果で遷移する、古い候補を採用する | 遷移目的、ゲート、候補検証、採用を別段階として観測し、取消・同一ファイル再検証・後着結果を確認する |
| 再開時のフォント差補正で原本、文章、所属や保存済み判定を変える | 原本B0と現在B1を分け、必要な枠拡大・最小平行移動・補正不能拒否、設定保存との分離を確認する |
| 二重利用、別名保存、外部変化、照合再試行で所有や内容を誤る | 実ファイル識別とパスの双方、所有期間、追加書込停止、明示照合、再試行の要求所属を確認する |
| 作業先・設定・移送の失敗で唯一正常内容や続きの作業を失う | 失敗後も旧成功内容・現在編集・必要画像を保護し、取消・再操作・別名保存と通知を確認する |

内容保護、誤成功・誤遷移、所有の競合を優先する。正常な保存と再開だけで、保存中の追加入力や取消後の状態を確認済みとしない。

## 層別の分担

| 確認層 | 対象境界・確認目的 | 分担理由と必要な依存 |
| --- | --- | --- |
| ユニット | 時計・キュー・ゲート、二系統番号、不変snapshot、B0/B1と設定の合成、フォント調整の幾何 | 時刻・配送順・固定前後・独立レイアウト結果を決定的に制御する。実ファイル所有や実フォントの成立は別層へ渡す |
| インテグレーション | Windowsの実ファイル、SQLite/PNG/ZIP、同利用者PC設定、2プロセス排他、保存・候補・現モデルの境界 | 現物と論理状態の一致、設定分離、実所有、正常な保存・再試行を確認する。物理保存段階の障害は保存整合性テーマの仕様を利用する |
| E2E・実機 | OS保存・開く・コピー、IME/ドラッグ、保存状態・モーダル・取消、別PC再開と標準フォント差 | 利用者の入力、表示、移送後の続きの作業を確認する。2PC・実配布物・実フォント対と台帳が必要であり、制御レイアウト入力だけで代替しない |

機能、設定分離、回復、整合性、所有競合、移送・環境互換性を観点として適用する。周期・順序を扱う機能確認と、所要時間の性能評価は分担を分ける。

## 網羅方針

| 網羅する判断群 | 技法・組合せ方針 | 設計へ渡す分割 |
| --- | --- | --- |
| 周期・設定・手動・状態 | 時刻表と状態遷移、dirty/clean、有効/無効、先行保存kind、最低番号、受付前後の確定内容の決定表 | 基点固定、pending集約、設定だけの合成、保存中追加入力、未確定入力、成功/失敗/後続未保存を分ける |
| 終了・切替・候補採用 | 未保存種別と保存/破棄/取消、取込・入力・実行中/受付済み保存、同一/別ファイル、候補取消・source変化の決定表と遷移 | 待つ順序、周期/設定停止再開、目的取消、再検証、採用前後、後着結果の行を持つ |
| 再開・移送・フォント差 | 保存属性の同値分割、元/先ハッシュ、原本有無、高増/減/保存属性無差、未所属/所属、範囲内/補正可/不能 | 単体移送と原本非依存、最小移動・必要拡大、B0/B1分離、未保存保護・履歴、候補全体拒否を確認する |
| PC設定・作業先 | 境界値、未存在/型/版/値域/IO、保存/取消/失敗、現セッション/次回、隣/指定/復旧採用の決定表 | PC固有とプロジェクト固有の範囲、次回適用、通知、専用領域、失敗後の旧値・編集・必要実体保護を確認する |
| 排他・再試行・非同期識別 | 元/別名パス/ハードリンク/別ファイル、所有生存/死亡、置換前後、記録と現物の一致/不一致/削除、照合中追加入力の状態遷移 | 所有の獲得と移管、blocked停止・明示照合、元要求の終端保持、後続保存、旧session/保存先guardを分ける |

具体的な保存項目、時刻、番号の算出、B0/B1/B2、フォント入力群と期待幾何は[DES-049の共通仕様](../test-design/DES-049-persistence-workflow-test-design.md#共通のデータ仕様環境要件手順)を管理元とする。戦略の分割を条件へ対応付け、各ケースの代表値・操作順で再現する。

## 観測・制御方針

保存では要求/セッション/遷移目的/保存先/transaction、受付・固定・実成功・通知、現在と保存成功の両番号、要求最低番号、snapshot、キュー/pending/blockedと周期基点を観測する。現物の全項目・PNG集合・ハッシュと現在編集を照合し、実成功に至らない終端を保存済みとしない。

読込では候補原本と端末調整後B1、検証・採用・所有移管、新セッション、実表示/入力/未保存を観測する。PC設定の現物・適用値・適用先、別PCのフォントと再開内容を別に記録し、設定保存への混入や遷移取消後の採用を判定する。

制御能力として、固定前後、候補検証/採用前、取込表示終結、IME/ドラッグ、周期、設定・保存失敗、後着通知、ロック確認、作業先ACL/容量を要求する。実物とダブルの使用箇所を分け、物理段階障害は保存整合性テーマの具体仕様に従う。既存フックの存在や製品試験結果は仮定せず、具体観測・制御・後片付けはDES-049と障害主本文に残す。

## 未決と引継ぎ

| 種別 | 本テーマの扱い・引継ぎ |
| --- | --- |
| 上流・製品設計への同期 | 変更後REQの合意レビュー、Ctrl+SのDES-006確定とDES-007候補の差、PC設定の閉じ方・未確定入力の実手段・表示案の同期を各担当へ返す。戦略分離で合意済みに変更しない |

## 設計への具体化とレビュー

本書の通常見出しを判断の参照先にし、[DES-049の戦略判断の具体化](../test-design/DES-049-persistence-workflow-test-design.md#戦略判断の具体化)で対応COND群・共通仕様・未決を示す。CASEへの接続は既存CONDを経由し、データ・操作・期待結果を戦略に複製しない。

レビューでは、判断から条件と共有データへ到達でき、保存受付/固定/実成功/表示と候補検証/採用を分けた観測がケースへ具体化されていることを確認する。準備・試験実行・製品評価は後続担当へ渡し、文書の完成と試験合格を区別する。
