# DES-055：画像取込・変換のテーマ別テスト戦略

- 設計状態：ドラフト。既存の取込テスト設計からテーマ全体の方針を分離した。製品の振る舞い、受入基準、要件合意、ADR状態を変更するものではない。
- 戦略区分：テーマ別。
- 上位戦略：[DES-013：共通テスト戦略](DES-013-common-test-strategy.md)。根拠と判定の扱い、層と品質観点の区別、共通の証拠・未決・担当境界は上位戦略に従う。
- 具体化先：[DES-047：画像取込・変換のテスト設計](../test-design/DES-047-image-import-test-design.md)。COND・CASE、データ仕様、具体環境・観測・準備・操作・後片付け、既存未決の正本を維持する。
- 参照要件：[REQ-001](../../product-requirements/functional-requirements/collection/REQ-001-add-image-path.md#受入条件)、[REQ-002](../../product-requirements/functional-requirements/collection/REQ-002-static-image-formats.md#受入条件)、[REQ-003](../../product-requirements/functional-requirements/collection/REQ-003-batch-import-errors.md#受入条件)、[REQ-034](../../product-requirements/non-functional-requirements/collection/REQ-034-image-conversion-timeout.md#受入条件)。全受入条件が対象。各本文のドラフト状態と未決を維持する。
- 依存設計：[DES-010](../functional-design/collection/DES-010-image-import-pipeline.md)、[DES-043](../non-functional-design/collection/DES-043-image-conversion-resource-controls.md)、[DES-004](../data-design/DES-004-board-data-model.md)、[DES-008](../data-design/DES-008-project-file-data.md)。
- 分離関係：DES-047の冒頭とテーマ全体の方針を本書へ整理した。設計に含まれる条件固有の技法・優先理由・確認層・観測方法は、方針を適用した分析・具体仕様として残す。

## 対象範囲と検証目的

ローカルの選択・ドラッグ、Chrome/Edgeの画像コピー・ドラッグから、選択した画像の取得、先頭静止画化、内部PNGへの変換、配置・表示までを確認する。成功分を保持して失敗対象と理由を識別でき、変換打切りや後続処理によって既存内容・原本を失わないことを重視する。

製品受入ではREQの入力経路・形式・変換属性・部分成功・時間制限を確認する。DESの入力保持、URL取得、ICC処理、寸法丸め・派生、初期配置、Job Object、表示終端は技術契約の確認として切り分ける。共通戦略の根拠区分を、同じ取込経路の観測に適用する。

本テーマは取込機能と取込ワーカーの制御を扱う。プロジェクト全体の安全読込、保存段階の復元保証、表示キャッシュ予算、時間性能、配布成立は他テーマの担当である。取込元の容量・寸法の実取得検査と拒否時保護は本テーマで確認し、数値・境界共通データは資源テーマの管理元を参照する。

## 主要リスクと優先順位

| 主要リスク | 優先理由・確認する保護 |
| --- | --- |
| 非同期取得による入力消失、取得源や対象の取り違え | 全利用の入口である。イベント終了後も必要入力を保持し、実ブラウザの取得源と取り込んだ内容を対応付ける |
| 先頭画・色・向き・寸法の誤解釈 | 参考画像の意味を変えない。原本、生成PNG、保存後のPNGと実表示を独立期待値で照合する |
| 混在失敗や期限超過で正常分・既存内容を失う | 成功・失敗の位置を変え、個別終端と後続継続、対象・理由通知を確認する |
| 巨大入力、作業領域失敗、制限未成立のワーカーが継続する | 拒否・打切り時も旧モデルと正常画像を保護し、ワーカーの同時数・メモリ制限・親子寿命を実物で確認する |
| 古い配置候補、途中成果、表示前の終端を採用する | 受付・変換・候補・追加直前・表示を別段階として観測し、同時編集後の再検査と画像参照保持を確認する |

優先順位は内容保護と終端誤判定のリスクから付ける。形式の正常確認だけで、失敗後の保護・継続や非同期競合を確認済みとしない。

## 層別の分担

| 確認層 | 対象境界・確認目的 | 分担理由と必要な依存 |
| --- | --- | --- |
| ユニット | 入力源の選択、寸法・配置の独立計算、受付状態、期限・候補の状態遷移、巨大ヘッダーの安全な検査 | 境界値と配送順を決定的に制御する。時計、イベント終了、取得結果、候補応答を差し替え、実ブラウザや変換エンジンの成立は別層へ渡す |
| インテグレーション | HTML5入力と取得処理、Rustと実画像エンジン・コーデック・色管理、Workerと現行モデル、Windows Job Object、PNG登録と表示処理 | 実物依存により形式・メモリ制限・終了・配置競合が成立することを確認する。低層の値判定と実取得・全面変換の保護を分ける |
| 実機・E2E | OS選択、実クリップボード、Chrome/Edgeの各経路、混在失敗・通知、配置・実表示、保存して再開した画像 | 利用者が選択した対象と得た画像を結ぶ。通知やDTO到着だけで実PNG・実表示を代用しない |

機能・互換性・データ整合性・回復・競合・資源制御を各層の目的と結び付ける。変換期限とワーカー制限の契約確認は、500枚取込の時間性能評価とは分担する。

## 網羅方針

- 経路と形式、ブラウザと操作を決定表として整理する。選択取消、直接画像・URLだけの入力、名前/MIMEと実形式の相違を別条件にする。
- 先頭コマ・先頭ページ、寸法の例と境界、色空間・ICC・透過・向き情報を同値分割する。表示寸法と保存画像寸法、色情報属性と未決の数値色比較を区別する。
- 正常・混在・全失敗、失敗位置、変換開始を基点とする期限、異常終了・メモリ不足・Job登録失敗・親終了を状態遷移で扱う。取込元の各上限は直前・一致・超過と入口を対応付ける。
- 配置は受付時の固定値、予約と失敗、候補計算後の編集、追加直前の再検査を組み合わせる。変換成功と配置・表示終結、表示失敗後の参照保持を独立に確認する。

具体的な値、時刻、入力順、配置式、正常/異常パラメータは[DES-047の共通仕様](../test-design/DES-047-image-import-test-design.md#共通のデータ仕様環境要件手順)とCOND・CASEで管理する。

## 観測・制御方針

入力の識別と順、取得・変換の開始と終結、PID・失敗分類、原本と生成PNGの属性・ハッシュ、asset登録、候補と現行モデル、実描画、取込終端と参照集合を関連付ける。原本・生成・再開後の三点比較と、内部段階・画面結果の対応を必要な証拠とする。

制御が必要な境界は、入力イベント終了、HTTP応答・接続・取得期限、変換時計・停止・異常終了、Job登録、作業領域書込、候補返却・追加直前、表示失敗である。実物のワーカー制限とAPI失敗はユニットのモデル制御と区別して記録する。具体的な観測項目・障害の適用手順は設計が管理し、必要能力がない境界は製品設計へ返す。

## 未決と引継ぎ

既存未決の正本は[DES-047のレビュー・引継ぎ](../test-design/DES-047-image-import-test-design.md#レビュー引継ぎ)。本書では戦略判断への影響を示す。

| 残る内容 | 判断への影響と戻り先 |
| --- | --- |
| URL自動取得、壊れたICC、初期配置、配置/表示失敗のREQ照合 | 現REQ受入とDES契約を分けた範囲で進め、変更後受入前の上流反映・レビューを要件/製品設計担当へ返す |
| 異なるICCの数値比較・縮小透過輪郭の評価方法 | 該当比較だけに影響する。固定sRGB入力の既知画素・α・bit深度・向き・寸法・原本保護は独立確認し、無根拠な許容差を設けない |
| 失敗理由の詳細分類・表示文言 | 意味・対象・段階・モーダルと保護を先に確認し、文字列の完全一致を要件へ追加しない。製品設計で同期 |
| 実入力、ページ、ビルド・依存版、段階・実障害制御 | 実装・検証担当へ準備仕様を渡す。実ブラウザ、実画像処理、実Job制限、実表示の証拠が必要 |
| 性能評価条件 | 性能テーマの未決を参照し、独立した本テーマの機能設計を進める |

## 設計への具体化とレビュー

本書の重要判断は普通の見出しを参照先とし、[DES-047の戦略判断の具体化](../test-design/DES-047-image-import-test-design.md#戦略判断の具体化)でCOND群・共通仕様へ対応付ける。CASEは既存のCOND対応を通して追跡し、本書にケース本文・具体データ・手順を複製しない。

レビューでは層の目的、全経路・形式・失敗/競合の方針、必要な実物証拠と他テーマ境界がCOND・CASEへ具体化されていることを確認する。観測方法の不足は製品設計、入力/手順の不足はテスト設計へ戻す。上流差分と色比較方法の影響は該当範囲に残し、文書整理を実行準備・製品試験合格にしない。
