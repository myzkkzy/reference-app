# DES-013：詳細設計の成立確認と検証への引継ぎ

- 設計状態：ドラフト。文書整備と引継ぎの方針。試作・具体的試験計画・製品試験は未実施。
- 目的・範囲：方式の成立確認で先に確かめる事項、受入評価への対応と引継ぎ。具体的操作手順・固定画像ファイル・実測結果は検証担当が`docs/product-verification/`で管理し、本書は合否基準を追加・緩和しない。
- 入力確認日：2026-10-09。ユーザーの詳細設計・IPC契約反映計画とHTML5入力を含む対話回答を要約。方式選択、要件全体の合意、ADR採用、設計完了、製品試験合格を区別する。
- 参照要件：[要件一覧](../../product-requirements/index.md)のREQ-001～033。各本文・受入条件・状態を正本とする。特に[REQ-029](../../product-requirements/cross-cutting/REQ-029-image-and-project-limits.md)と[REQ-033](../../product-requirements/cross-cutting/REQ-033-performance-evaluation-conditions.md)の上限・共通条件を維持する。
- 関連判断：[ADR-009](../architecture-decisions/2026-09-29-ADR-009-test-automation.md)。実装時のテスト基盤採用と実行結果は別に扱う。

## 製品評価へ渡す条件

既存の500枚評価条件と全3回合格を維持する。500枚は登録上限ではない。固定画像の実ファイル、JPEG350・PNG100・WebP20・GIF10・TIFF10・BMP10の内訳、1920×1080、配置・メモ・グループ・設定と評価環境はREQ-033に従って検証担当が台帳化する。ローカル500枚取込とブラウザURL取得の別条件を混ぜない。

通常操作100ms／細部1秒、保存中操作500ms／細部2秒、保存済み500枚の再開5秒、ローカル500枚取込30秒を対象要件どおり判定する。対象ビルド・OS・固定WebView2版、Core i5-1235U・16GB・内蔵GPU・SSD・FHDの条件、起動／再実行の条件をREQ-033と照合し、条件の省略・数値の緩和で合格にしない。

観測点は入力イベント、要求受付、スナップショット固定、DB生成、ZIP完了、置換・復旧完了、候補検証、PNGデコード、描画・操作可能化とする。保存中にパン・ズーム・編集を続け、古い保存番号で新編集を保存済みへ進めないことを確認する。表示完了は要求した解像度が実際に描画され操作可能であることとし、低解像度の仮表示だけで細部完了にしない。

## 文書レビューの完了条件と残件

設計一覧と全対象REQの対応、本文・図・ADR・型・保存対象の整合、OKFメタデータと厳格リンク、未決事項の担当・時期・解消条件を確認する。実装引継ぎ可能への遷移は、必要な上流反映・レビューと方式の成立確認結果を確認した範囲で判断する。

DES-011と分割先DES-014～039の通信契約の選択・物理名・型は決定済み。現在の残件は、要件本文への差分反映と変更後レビュー、固定する具体的依存ビルドと配布台帳、Windows実機の入力／描画／配布成立確認、性能・障害の実証である。方式の選択を未回答として再質問する必要はない。具体的な試験計画と結果を本書に架空で追加しない。

## IPC契約の共通評価観点

今回の契約変更は文書に反映済み。コマンド・通知・複合型の物理名、型、必須性、省略条件、判別型、寿命と終結を定義した。方式の成立確認と上流レビューを残すため、設計状態は評価待ちとする。テンプレート・設計手順の8列規則は既存のプロジェクト規則を利用し、エージェントの設定変更を必要としない。

| 評価対象 | 確認する境界 | 引継ぎ・解消条件 |
| --- | --- | --- |
| 実Tauriの転送 | HTML5／OS選択、最大1MiB・全体1チャンク、再送・不一致、入力ごとの取得失敗、UTF-8 JSON・PNG Response | 実装・検証担当が固定版WebView2・Tauriで実データとヘッダー／本文を観測 |
| 取込と画像参照 | 通知がacceptedより先、結果欠落回収、変換完了と表示終結、同期番号の古さ、ボード／履歴／バッチの保持 | 実装・検証担当が部分失敗・配置／表示失敗・解放後再表示を実証 |
| 保存固定・実行 | 集約代表通知、settings専用本文、番号不足、Worker失敗、古い／重複供給、固定後編集、照会・受領確認 | 実装・検証担当が保存中反応、固定対象とDB・PNG・実保存番号を照合 |
| 候補・ゲート | 採用前外部変更、同一ファイル再読込、ロック貸与・移管、戻ると後着結果、採用応答欠落 | 実装・検証担当が旧状態保護と一度だけの移管を確認 |
| 中断・初回・復旧 | 中断終結と新transactionIdの後続保存、初回失敗・断念、元欠損探索、別名保存前のコピー保持 | DES-009の置換前後障害・排他評価と同じ保護境界で実証 |
| 上流・性能 | 要件差分レビューと既存500枚・全3回条件 | 要件担当は変更後の振る舞いを照合。検証担当は[DES-013](#製品評価へ渡す条件)で台帳化・評価し、基準を緩めない |

文書形式・内部リンク・8列表の検査は契約の整合確認であり、実装や製品試験の合格ではない。実証で方式が成立しなければ、結果と変更影響を記録して[IPC契約の定義元一覧](../functional-design/DES-011-ipc-contracts.md)・ADR-016を見直す。
