## 検証目的と主要リスク

各上限の一致を含め、全条件を満たす候補だけをまとめて採用する。数値の容量判定と、実ファイルが正常構造で読めることを別に証明する。不正・過大候補を一部採用したり、修復・縮小して読み替えたりせず、入力と現在の編集を保護する。

| 主要リスク | 本テーマの検証判断 |
| --- | --- |
| 上限一致の誤拒否、桁落ち、件数・共有実体の数え違い | 直前・一致・超過を独立に確認し、構造上のページ粒度と整数述語の境界を分ける |
| 申告値だけで巨大出力を展開する、入力の経路・SQLが外部を変更する | 実出力量・検査順・停止点を観測し、専用領域と原本を保護する |
| 最後の不正要素を検出する前に候補の一部が現在状態へ混ざる | 全体検証と採用の境界を確認する |
| 予算超過後に割り当てる、共有・取消で二重計上や二重解放が起きる | 予約→開始→移管→解放の台帳と、キー別の所有・同時数を確認する |
| 仮表示や受信・デコードを実表示完了と誤認する | 要求解像度・対象画像・実描画を照合し、時間性能とは別に判定する |

## 判定の種類と層の分担

容量上限と不足時保護はREQ-029の条件である。CPU256MiB、GPU推定512MiB、読込・デコード合計同時2件はDES-042の初期技術設計値として確認する。これらを新しい製品受入値、時間性能の達成、OS・ドライバーの総使用量の条件へ昇格させない。500枚は性能の評価負荷であり登録上限ではない。

| 確認層 | 確認する境界・証拠 | この層を使う理由 |
| --- | --- | --- |
| Unit | サイズ・件数・総量の整数述語、候補採用、資源寿命とピーク計算、予約・共有・取消・同時数 | 厳密境界と競合順序を制御し、他制約が先に拒否する結果から誤って網羅を推定しない |
| 結合 | 実SQLite・ZIP・PNG、実ストリーム、固定DB防御設定、実表示キャッシュ・所有と予約 | 構造正常な境界資料、ZIP64、申告と実量、実依存の処理停止と副作用を確認する |
| E2E・実機 | 現在編集と入力の保持、候補の全体採用、資源不足通知・操作継続、実Canvas／WebGL描画 | 内部検査が利用者の状態保護と実表示へつながることを確認する |

旧DES-013の大容量ZIP64・DB防御の成立確認は、実物結合で全正常内容を読めること、DB外PNGも全体照合することを優先する判断として継承する。小量ZIPや壊れた境界資料の拒否だけではこの成立を判定しない。

## 網羅方針

- 取込元・内部PNG・manifest・DBの寸法と実サイズ、ZIP件数・要素数・展開合計・全体サイズを独立に確認する。正常資料では他制約を適合させ、作成・編集・保存の経路でも同じ条件を照合する。
- 数値比較の±1と、正常な実SQLiteのページ粒度を分ける。PNG・大規模ZIPの厳密サイズと複数上限が同時成立する実物を準備条件にする。
- ZIPの名前・経路・重複・リンク・必要集合、DBのスキーマ・必須行・型・防御設定、ID・数値・PNG参照と全デコード、形式版を個別変異で確認する。申告値と実出力量は別の検査対象とする。
- 作業先・保存先の同一／別ボリューム、共有実体、資源寿命の重なり、照会後の空き減少を含む。内容上限を必要空き容量へ読み替えない。
- 表示資源は共有と一時・保持資源、CPU／GPUの別計上、解放で足りる／足りない、画面外／未使用／使用中を区別する。読込・デコードは別々の上限にせず全体合計を観測する。
- 同じキーの複数要求元、最後の所有解除、取消不能の後着、旧セッション結果を含む。受信・デコード・実描画を段階別に観測し、低解像度の仮表示を細部完了にしない。

境界数値・正常対照・変異資料・代表解像度はDES-052の共通仕様を管理元とする。テーマ戦略へ境界値表やケース本文を複製しない。

## 観測と制御の方針

検査した申告値・実量・構造・拒否理由・停止点、候補と現在状態の識別、ボリューム別見積、予約・active・所有台帳を関連付ける。DBの整合検査・外部参照・アプリ制約、PNGのハッシュ・サイズ・寸法・全デコードは別結果として扱う。

ストリーム出力、I/O失敗、予約不足、読込・デコードの保留、取消不能、旧結果を制御できる能力を後続へ渡す。実結合では専用一時領域外の監視物と原本の前後状態を確認する。全PNGの同時展開を検査の前提にせず、GPU予算は推定式と割当台帳を使う。

実表示は対象画像と要求解像度を画面証拠へ結び付ける。フレーム・実描画の観測方法が得られなければ実画面確認を組み合わせ、不能な範囲は製品設計へ返す。具体的な時間測定法・細部性能の評価条件は性能テーマの未決に従う。

## 未決事項と引継ぎ

容量値・不足時保護に新たな未決閾値を追加しない。変更後REQ-029のレビュー・合意とADR-012の採否は担当へ返す。性能の固定対象・操作・計測法はDES-053の未決を維持し、容量・構造・資源寿命の独立した判定を進める。

実装担当へサイズ・実ストリーム・候補採用・予約・取消・所有の観測制御を、検証担当へ構造正常な境界資料、大規模ZIP64、ページ粒度、必要ピーク容量と独立台帳を引き継ぐ。実物がまだ存在しない境界を不正資料の拒否で代用せず、後続準備不足として残す。具体的な仕様・必要証拠は[DES-052の共通仕様](../test-design/DES-052-resource-validation-test-design.md#共通のデータ仕様環境要件手順)と[レビュー・引継ぎ](../test-design/DES-052-resource-validation-test-design.md#レビュー引継ぎ)を正本とする。
