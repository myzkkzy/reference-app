## 共通のデータ仕様・環境要件・手順

### 保存状態・設定・番号の管理元

本節を保存機能フローの論理状態、共通設定、フォント調整の管理元とする。各テーマの障害資料等はこの役割を維持し、差分の具体値を当該ケースへ記す。B0/B1/B2は内容の役割名で、更新番号そのものではない。実データ/台帳/環境の作成は後続担当。

| 識別 | 具体仕様・比較対象 |
| --- | --- |
| P0/B0/view0/S0 | DES-048のB-Eを保存する。差分はI1中心(120.125,-40.5)/角45/scale0.5、G1枠(-300,-200,900,900)、N1本文「A\nBC」/幅320/font18、z順I2,N2,N3,I1,N1。G3空枠も保存。view0中心(123.125,-456.5)/zoom0.25。S0はautosave/recovery/grid_visible/snap_enabled=有効、grid_spacing32、rotation_snap_deg15。全項目・PNG集合・SHA-256を独立台帳化 |
| 通常編集B2/view2 | I1中心へ(+64,+32)、N1本文「AB\nBC」、G1枠必要拡大または手動変更、view中心へ(+10,-20)/zoom0.5。各ケースは必要な差分だけ確定し番号を記録。未確定ドラッグ/IMEは確定状態に混ぜない |

番号はDES-009のboardRevision/savedBoardRevision、およびアプリ寿命のappSettingsRevision/savedAppSettingsRevision。board/viewの確定変更と設定変更を別に記録し、u64十進文字列の通信詳細はDES-051。例示番号を内容ラベルから推定せず、操作列の各確定時点で期待番号を独立算出する。設定だけ成功は現在board成功番号を進めず、編集中/IME等は番号が同じでも未保存表示を要する。新セッション採用時はボード2番号0、アプリ設定番号は維持、フォント調整の保存属性変更があればboardRevisionだけ1、savedBoardRevisionは0。高さ再計算だけなら0。

### 時計・キュー・操作ゲート

| パラメータ列 | 制御する具体時点と期待する順序 |
| --- | --- |
| 固定周期 | 利用開始/有効化t0=0。編集5、手動保存12、追加編集20、定期30/60/90。編集/手動で起算点を変えない。有効化70の行だけ新周期100/130 |
| 重複周期 | 定期30で固定/保存中保留、60/90に周期到来、編集35/91、95で先行完了。pendingは最大1、最新未保存があれば後続1回、次周期120。無追加編集行は完了時cleanなら後続なし |
| 手動要求 | 先行固定→追加確定→手動受付M1→追加確定→手動受付M2→さらに追加。要求ごとの最低board番号と実成功番号を対応付け、受付/古い成功だけでM1/M2を完了しない |
| 操作ゲート | 取込の配置/表示終結まで待つ→定期ボード保存を止める（設定保存の停止はアプリ終了目的だけ）→実行中/受付済み手動の終端を待つ→未確定入力解消→board/view未保存確認→最新のready結果で目的操作。戻る/取消は遷移目的だけ取消し、遅い保存成功で閉じる/切替しない |

時計を制御するユニット/結合では指定時点を決定的に再現し、実機では単調時計・基点・処理段階の観測記録で同じ目的を確認する。新しい性能基準、試行数、周期の許容差を追加しない。

### フォント差データの管理元

本文/幅/fontSizeは固定し、旧/新PCの標準フォントで行割が変わるデータを後続担当が選定して台帳化する。ユニットの行割・高は次表の独立レイアウト結果を制御入力として使い、実フォントの存在/結果が確認済みとは扱わない。実物確認では本文・両PC標準フォント・幅・行割・高の実測を残す。

| フォント入力群 | B0と新レイアウトB1の具体値/期待 |
| --- | --- |
| F-GROW | メモ左上(0,0)、幅120/font16、旧1行H0=64→新2行H1=88。G枠(-24,-24,168,112)、同所属画像16×16中心(80,20)。必要枠は(-24,-24,168,136)、通知/未保存。新高減少行は旧H88→新H64でも旧枠136を縮めない |
| F-MOVE-N | 未所属メモ左上(100,999936)、幅120/font16、H64→88。新外周下端1000024をY=-24だけ補正、X不変。本文/幅/font/保存view不変、調整対象の通知なし |
| F-MOVE-G | G枠(-24,999888,168,112)、メモ左上(0,999912)、同所属画像16×16中心(80,999930)。H64→88、必要枠高136の後にG/全所属をY=-24だけ移す。新G左上(-24,999864)、相対配置保持 |
| F-HEIGHT | H64→88だが未所属で範囲内、または大きな保持枠で拡大不要。保存属性に差なし、clean/履歴空 |
| F-REJECT | G枠(-24,-1000000,168,2000000)。上端側の画像16×16中心(80,-999968)、下端メモ左上(0,999912)/H64。新H88では必要高2000024、相対配置維持の平行移動で±1000000に収まらず候補全体拒否 |

B0は読込した原本と最後の保存基準、B1は端末レイアウト調整後の現在状態として分離する。設定だけの保存にB1を混入させない。必要最小移動は、各超過軸について元外周を[-1000000,1000000]へ包含する平行移動量で独立算出し、超過していない軸は0、スナップなし。幅/本文/font/相対配置を変更する代替補正をしない。

### 環境・観測・準備・後片付け

- 実物結合：Windows 11、通常利用者権限、実SQLite/PNG/ZIPとローカルファイル操作、同じアプリ配置先の設定先、2プロセス、別PC2台。ビルド/固定WebView2/依存版/ボリューム/権限/フォント/IMEを台帳化する。具体版は未準備で要件合意の未決と分ける。
- 層分担：時計・キュー・ゲート・番号・B0/B1と設定分離はユニット/状態結合、実排他/置換/設定ファイルはWindows実物結合、OS保存/開く/コピー/IME/状態表示/別PCは実機/E2E。
- 観測：要求/セッション/遷移/保存先/固定対象/transactionの識別、ボードとアプリ設定の独立した現在・成功番号、要求最低番号、snapshot、キュー/pending/blocked、周期基点、候補原本/B1/採用、現物ハッシュ/全保存項目/PNG集合、共通設定/適用先、実表示/入力/未保存。
- 制御：固定前後/終端、候補検証/採用前、取込表示終結、IME/ドラッグ、周期、設定/保存失敗、後着通知、ロック確認、作業先ACL/容量を制御できる仕様を渡す。実装済みフックや物理APIを補作しない。段階障害の制御仕様/安全な資料はDES-050。
- 共通準備：使い捨て保存/作業/設定の試験領域を用意し、PC既存設定と入力の独立保護コピーを確保。P0を保存成功させ現物/番号を確認、各行の差分と制御順を作る。PC実設定試験は検証用アプリ配置先を分離して既存設定を保護する。
- 共通後片付け：証拠を回収、障害/時計/通知/保留を解除、進行処理を終結、プロジェクトを正常終了し所有解放を確認。共通設定・試験フォント/IME/ブラウザを戻す。唯一正常コピー/未完了記録/復旧候補/帰属不明ファイルを無条件削除しない。実体後片付けの正本はDES-050/052。
- 準備物：実データ/原本台帳、独立ファイル読取、時計/キュー/番号/段階の観測制御、実ロック/ハードリンク等の識別、別PC/フォント対、OS操作の実現。実装・検証担当が実行計画で用意し、文書の仕様を実物準備完了や試験合格としない。
