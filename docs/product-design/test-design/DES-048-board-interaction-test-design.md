## 共通のデータ仕様・環境要件・手順

### ボード・メモデータの管理元

本節をボード/メモ/操作座標の管理元とする。実データ生成は後続担当。数値はボード単位、表示zoomは1=100%、画像倍率は1=100%。画像中心、メモ左上、枠左上を混同しない。モデルは有限64bit浮動小数を保持し、期待座標はDES-004/006の式から独立計算する。整数化して期待結果を丸めない。画像入力はDES-047の管理元から再利用する。

| 識別 | 基準データB-E（ケースの差分が優先） |
| --- | --- |
| I1 | 200×100 PNG、中心(0,0)、角度0、画像倍率1、z=1、G1所属 |
| N1 | 本文「A\nBC」、左上(-100,200)、外幅320、fontSize=16、z=2、G1所属。2行を折返しなしで表示 |
| I2 | 120×120 PNG、中心(400,0)、角度45、倍率1、z=3、未所属 |
| N2 | 本文「別所属」、左上(600,200)、幅320、fontSize=16、z=4、G2所属 |
| N3 | 本文「未所属」、左上(600,400)、幅320、fontSize=16、z=5、未所属 |
| G1/G2/G3 | G1枠(-160,-100,440,500)、G2枠(550,150,440,200)、G3空枠(-600,-400,64,64)。全枠が外周範囲内で内容+各辺24を包含する |
| 表示・設定 | 中心(0,0)、zoom=1、グリッド表示/吸着オン、間隔32、回転刻み15。通常操作の期待を分離する行では吸着をオフにする |
| ID | 各要素/枠は別の小文字UUIDv4。例I1=`00000000-0000-4000-8000-000000000001`。対応台帳に固定し、更新・Undo後も同じIDを照合 |

メモ高は本文の折返し/明示LFの行数、通常ウェイト、PC標準フォント、1.5倍行高、内側8、ヘッダー24、最低1行から独立算出する。2行/font16なら`24+16+2×24=88`、空の1行なら64。幅は外幅で、入力幅と描画幅に同じ内側余白を適用する。具体的なPCフォント名や高さは保存列にしない。標準フォント取得/代替と別PC調整の正本はDES-004/049。

| TEXT-A | ASCII 9,999/10,000/10,001。貼付は10,000の[5000,5002)を選択し2クラスタ/3クラスタで置換 |

### 環境・観測・共通手順

- 製品受入：Windows 11、対象ビルド/同梱固定WebView2、実マウス・キーボード、日本語IME、OS標準フォント。ボード表示領域とクライアント論理寸法、zoom、DPIを記録する。ペイントアプリ1つの名/版は検証計画時に選定・記録する。
- 確認層：状態/幾何/履歴/計数はユニット、textarea/Pixi/Worker/保存境界は結合、利用経路/IME/フォーカス/前面維持/最小画面は実機/E2E。実入力や実描画をダブルだけで成立扱いにしない。
- 観測：前後モデル（ID・所属・z・位置・角度・倍率・枠・本文・幅・fontSize・表示）、ドラッグ開始/最終有効/プレビュー/確定、ボードUndo/Redoと文章内履歴、保存固定対象、両更新番号、実描画・補助線・フォーカス・通知を関連付ける。
- 制御：ポインター解放/取消、IME compositionの開始/確定/取消、保存対象固定/完了/失敗、候補の消失/画面外移動、PCフォント/表示領域。既存のフックを仮定せず、実装・検証担当へ必要な観測/制御仕様として渡す。
- 共通準備：各行はB-Eの使い捨てボード/入力素材へ戻し、原本ハッシュ・履歴・保存基準・表示を記録。必要時はDES-049の基準保存P0と失敗制御を参照する。
- 共通後片付け：証拠回収後にIME/入力を終了し、障害・DPI/フォント試験条件を戻し、通常終了。唯一の正常実体/復旧候補は消さない。作業領域実体の保護はDES-050/052。
- 実現方法・準備物：独立幾何計算/計数期待値、本文/画像台帳、実機操作と自動化可能部分のE2E、状態/保存境界の観測手段。実データ・コード・環境・実行計画/実行は後続担当。各ケースの未決は上流判定残件と実行準備を分ける。

## テスト条件

### COND-001

- 名称・確認対象：全体/細部表示、空/非空の範囲、無補正再開、メモ開始時の表示。
- 根拠：REQ-004全受入条件、DES-004表示式。区分：正常/異常。
- 確認層／種別・品質観点：表示ユニット＋実機/E2E、機能・描画整合性。
- 技法・網羅対象・理由：空/非空・外周の決定表、zoom境界、再開→手動→サイズ変更→明示fitの遷移。保存zoomと通常下限を区別する。
- 優先理由：参照の入口。観測・制御の見通し：独立fit式、表示領域/実外周、保存viewと履歴。
- 対応ケース：[CASE-001](#case-001)～[CASE-004](#case-004)。未決・影響：極端配置の実描画精度/成立は未確認、許容差を補作しない。

### COND-002

- 名称・確認対象：制作アプリ操作中の参照維持。根拠：REQ-005受入条件。区分：正常。
- 確認層／種別・品質観点：実機、機能・操作性。技法・網羅対象・理由：描画/パン/ズームの各操作とアプリ切替。方式自体を要求にしない。
- 優先理由：制作中の成果。観測・制御の見通し：重なり領域の画像可視と制作操作継続。
- 対応ケース：[CASE-005](#case-005)。未決・影響：アプリ名/版は後続準備、要件判断は確定。

### COND-003

- 名称・確認対象：画像移動・複数周回転・比率/対角固定拡縮・倍率外の保護。
- 根拠：REQ-006、REQ-028回転/外接矩形/制約、DES-006拡縮解法。区分：正常/異常。
- 確認層／種別・品質観点：幾何ユニット＋実機/E2E、機能・状態整合性。
- 技法・網羅対象・理由：倍率直前/一致/超過、固定点の不変条件、自由値/吸着/取消の遷移。
- 優先理由：原本と配置の誤変更防止。観測・制御の見通し：対角/角度/比率/画像倍率とviewを別採取。
- 対応ケース：[CASE-006](#case-006)～[CASE-008](#case-008)、[CASE-028](#case-028)、[CASE-033](#case-033)。未決・影響：実ポインター制御と描画証拠は準備残件。

### COND-004

- 名称・確認対象：画像削除・直後Undo・空グループと原本保持。
- 根拠：REQ-007全受入条件、REQ-027履歴。区分：正常。
- 確認層／種別・品質観点：状態ユニット＋E2E、機能・回復。技法・網羅対象・理由：未所属/所属唯一、削除→Undo/Redoの遷移。
- 優先理由：誤削除の回復。観測・制御の見通し：同一ID・属性・原本ハッシュ、画像実体寿命はDES-050。
- 対応ケース：[CASE-009](#case-009)。未決・影響：実体保持の主ケースと接続、判断未決なし。

### COND-005

- 名称・確認対象：所属の単一性、解除/空保持、手動枠/必要拡大/fit/最小枠、グループ移動。
- 根拠：REQ-008/009全受入条件、REQ-027/028、DES-004。区分：正常/異常。
- 確認層／種別・品質観点：状態/幾何ユニット＋E2E、機能・相対配置/更新単位整合性。
