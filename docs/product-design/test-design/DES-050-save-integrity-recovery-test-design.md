## 共通のデータ仕様・環境要件・手順

### 保存内容と比較対象

検証担当が使い捨ての保存先に生成する仕様。原本台帳と保護コピーは試験対象から分離する。

| 状態 | 固定内容・比較値 |
| --- | --- |
| 直前成功B0/S0 | 相異なるsRGB8bit PNG実体A=640×360、B=320×320。画像A中心(0,0)・B中心(640,0)、各scale=1・rotation=0、z_index=0/1。Aだけを含むグループ枠(-344,-204,688,408)。メモ左上(0,480)、本文「保存成功の本文」、幅320・font_size16・z_index2。表示中心(0,0)・zoom1。自動保存／復旧保持／グリッド表示／吸着は有効、grid_spacing32・rotation_snap_deg15。ID・PNGハッシュと全DB項目を台帳化 |
| 次のボード保存B1/S1 | Aを(64,32)へ移動、グループ枠を(-344,-204,752,440)へ必要拡大。元メモ本文を「次の保存対象」へ変更。S1はgrid_visibleだけ無効。各確定操作に対応する両更新番号を固定し、全PNG集合はA・B |
| 設定保存B0/S1 | 直前成功のB0/view0とA・B集合へ最新S1だけを合成。Aの移動・メモ本文等の未保存B1を混ぜない |
| 保存固定後のB2/S2 | Bを削除しUndoに保持。新メモ左上(960,480)、本文「保存中の追加入力」、幅320・font_size16・新規z_index3を追加。S2はS1に加えてgrid_spacing64。B1/S1との差分と両現在番号を固定 |
| 初回の空状態 | 空ボード・新規既定設定・既定表示。旧ファイルなし。作成候補の初回保存対象を固定し、旧成功内容を捏造しない |
| 復旧資料 | 本ZIP、.recovery、new、previous、prepare、complete、置換用退避、復旧用一時コピー。それぞれの帰属・SHA-256・実サイズ・完全検証結果を記録 |
| 画像保持資料 | A・BのPNG SHA-256とサイズ、表示縮小版256/1024、保持元別の参照集合。画像実体と再生成可能な表示キャッシュを別に列挙 |

保存ファイルはコンテナー1／DBスキーマ1とし、SQLiteの全保存項目とPNG集合を照合する。セッション番号はZIPへ保存しないため、稼働中の両現在番号／両成功番号と再読込後の保存内容を別の証拠として扱う。再開時の番号0を旧セッションの番号と比較して成功としない。

B0/B1/B2・S0/S1/S2は内容の識別名であり更新番号の数値そのものではない。台帳へ各確定操作後の実番号を記録する。ケース固有の保持設定行ではS0/S1のrecovery_enabledを当該行へ変え、その差分を明記する。特記のないケースは旧成功B0/S0がある既存保存を前提とする。初回保存の旧なし状態はCASE-009・010とCASE-018の明示行だけへ適用する。

### 環境と制御境界

- 実物を使う結合確認：Windows 11 x64のローカルファイルシステム、実SQLite・PNG・ZIP・同期・置換API、同じ保存先の本ファイルと一時領域。アプリ・SQLite・ZIP・OSの具体版、ボリュームと権限、固定WebView2版を実行側が台帳化する。
- Unit：保存状態・世代連鎖・更新番号・参照所有のモデルを使い、ファイルI/O・同期・時計・通知を差し替える。Unitだけで実置換・実同期・異常終了保護の成立を判定しない。
- 段階制御：下表の処理境界に到達した事実を記録し、当該操作の直前／直後を停止できる観測・制御口を実装担当が用意する。実装済みフックや物理API名を仮定しない。同期失敗、短い書込、容量不足、アクセス拒否、通知抑止を別に制御する。
- 強制終了は停止点到達後に対象アプリを終了し、試験用制御が追加の保存・後片付けを走らせず再起動する。停電を模した保証判定は行わない。
- 共通観測：requestId/sessionId/transactionId、保存kind、固定内容と両番号、各段階の開始・終了・同期成否、実ファイルの所在・ハッシュ・サイズ、成功／失敗通知、書込停止状態、採用された復元内容、保持元別画像集合。
- 重なった要求や通知の配送順は[DES-051の共通仕様](DES-051-ipc-contract-test-design.md#共通のデータ仕様環境要件手順)を使う。受付やDB commitを保存成功の代わりにしない。

### 強制終了の停止点と再開時の判定

既存保存の各行はボード保存／設定保存、復旧用保持有効／無効を別の実行行として扱う。初回保存はCASE-009で別評価する。状態の成立が観測できない行は実行準備不足であり、近似した待ち時間で代用しない。

| 停止点・操作順 | 必要な観測証拠 | 再開で保護・採用する内容 |
| --- | --- | --- |
| DB生成中／commit後close前 | 本ファイル未置換、完了記録なし | 旧成功B0/S0。本DB成功だけではB1/S1を採用しない |
| 新ZIP検証・同期後 | 新候補正常、本ファイル旧ハッシュ、完了記録なし | B0/S0。単に読める新候補を自動成功採用しない |
| 旧正常の独立退避をコピー中／検証同期後 | コピーの完全性と旧本ファイルの所在 | B0/S0。途中コピーだけを唯一の正常内容としない |
| prepare同期後、置換前 | prepare完全、本ファイル旧ハッシュ | B0/S0。記録した新旧を照合 |
| 本ファイル置換・照合後、complete前 | 本ファイル新ハッシュ、完全なcompleteなし、previous正常 | previousのB0/S0を直前成功内容として提示。新ZIPを自動成功採用しない |
| 置換した本ファイルの同期中／同期後、complete前 | 本同期の成否、新本ZIPとprevious、完全completeなし | B0/S0を保護。新本ZIPの同期だけで新保存成功にしない |
| 必要な.recovery更新中／同期後、complete前 | 同じtransaction、新本ファイル・previous、復旧更新の成否 | B0/S0を保護。保持設定にかかわらずcompleteなしでB1/S1を成功にしない |
| complete書込途中／同期失敗 | 部分記録または同期失敗 | B0/S0を保護。部分completeを成功証明にしない |
| complete完全同期後、成功通知前 | 完全completeと新本ZIP一致 | B1/S1、または設定保存のB0/S1を復元 |
| 成功後のZIP・退避整理中／prepare除去後 | 成功証明と新本ZIP一致。completeはまだ存在 | 新成功内容を復元。prepareがなくてもcompleteで照合 |
| complete除去後 | 新本ZIP正常、完了した処理の整理終了 | 新成功内容を通常読込できる。未完了の別処理は整理しない |

### 共通の準備と後片付け

準備は、保存先・作業先の空き容量を確認し、B0/S0を保存成功させて成功証拠を採取、原本台帳・独立保護コピーを作り、ケースのB1/S1と停止点を用意する順とする。保持無効の行では既存.recoveryも別ハッシュで置き、無効化による削除・更新を検出できるようにする。

後片付けは、障害・通知・停止制御を解除し、稼働中の処理を終結または記録付きで停止、全証拠を回収、プロジェクトを閉じて所有解放を確認する。ケースが保護した唯一の正常コピーと未完了記録を証拠回収前に削除しない。検証担当が所有する使い捨て領域だけを整理し、整理失敗を保存失敗へ読み替えない。

### COND-001

- 名称・確認対象：保存成功の厳密な境界。
- 根拠：[REQ-037](../../product-requirements/non-functional-requirements/cross-cutting/REQ-037-saved-content-durability.md)「保存成功と復元の保証範囲」、[DES-041](../non-functional-design/cross-cutting/DES-041-save-integrity-and-recovery.md)「書込と成功境界」。
- 区分：正常／異常。
- 確認層／種別・品質観点：結合・E2E／整合性・耐久性。
- 技法・網羅対象・選定理由：段階と通知の順序を分ける。DB成功・ZIP正常・complete同期を区別する。
- 優先理由：保存済み誤表示と新旧逆転を防ぐ。
- 観測・制御：段階停止、完全記録と実ZIP・両番号の照合。

- 名称・確認対象：保存未開始と保存途中の異常終了。
- 根拠：[REQ-037](../../product-requirements/non-functional-requirements/cross-cutting/REQ-037-saved-content-durability.md#受入条件)第1行の保存成功後に未保存変更がある状態のクラッシュ・強制終了、および保存途中・設定保存・置換後・保持無効の異常受入条件。

- 確認層／種別・品質観点：結合・E2E／耐久性。

- 優先理由：直前成功内容の喪失を防ぐ。
- 観測・制御：未開始行の保存要求・処理なし、保存途中行の停止点到達、異常終了・再起動、正常読込または候補検証と選択。
- 対応ケース：[CASE-002](#case-002)、[CASE-009](#case-009)。
- 未決・影響：判定契約は本文へ具体化。変更後要件レビューと実物・観測制御口の準備は[レビュー・引継ぎ](#レビュー引継ぎ)で区別する。

### CASE-001

- 名称・確認目的：成功境界と固定後編集の保存番号。

- 確認層／種別・品質観点：結合／整合性。
- 前提・環境要件：[共通仕様](#共通のデータ仕様環境要件手順)の実物・段階制御を使用。特記がなければ旧成功B0/S0がある既存保存。旧なしを明示したケースだけ初回仕様を適用する。
- 入力・データ仕様：B0/S0→B1/S1のボード保存、別行でB0/S1の設定保存。固定後にB2/S2を作る。
- 準備：共通準備後、DB commit後・ZIP同期後・complete同期前で一時停止できるようにする。
- 操作・事象：各停止点で成功通知と両成功番号を確認して再開し、complete同期後・通知前も確認する。最後に本ZIPを別読込して内容を比較する。
- 期待結果と根拠：DB commit・ZIP正常だけでは成功番号を進めない。complete同期後の成功内容は固定対象のみ。B2/S2を巻き戻さず未保存に保つ（[REQ-037](../../product-requirements/non-functional-requirements/cross-cutting/REQ-037-saved-content-durability.md)、[DES-041](../non-functional-design/cross-cutting/DES-041-save-integrity-and-recovery.md)）。

- 後片付け：共通後片付け。事前保護コピー・当該正常候補の証拠を回収してから所有する使い捨て資料だけを整理する。
- 実現方法・準備物：実SQLite/ZIPを使う結合。後続担当が段階観測と固定後編集の操作を用意。
- 未決・影響：物理制御口・実ビルド・資料は後続準備未完了。期待する保護を変更する場合は製品設計/要件へ返し、観測不能な行を試験済みとしない。

### CASE-002

- 名称・確認目的：保存未開始とcomplete前の異常終了から最後の成功内容を復元。
- 対応条件：[COND-002](#cond-002)。
- 確認層／種別・品質観点：結合・E2E／耐久性。
- 前提・環境要件：[共通仕様](#共通のデータ仕様環境要件手順)の実物・段階制御を使用。全行は旧成功B0/S0がある既存保存に限定する。初回保存は[CASE-009](#case-009)で扱う。
- 入力・データ仕様：次の行を独立した初期状態から実行する。未開始行へ保存途中の停止点やprevious必須条件を適用しない。

| 独立行 | 入力・保存状態 | 異常終了の条件 |
| --- | --- | --- |
| 保存未開始 | B0/view0/S0の保存成功と整理が終結済み。画像A移動・グループ枠拡大・メモ本文変更だけを行い、共通B1のボード内容と編集履歴を未保存で持つ。view0/S0は変更しない。保存要求・待機保存・実行中保存はない | クラッシュ相当のプロセス異常終了／外部からの強制終了を別行。周期の発火を制御して新保存を始めず、設定変更・手動保存・正常終了保存も起こさない |
| 保存途中 | 共通B1/S1のボード保存／B0/S1の設定保存。停止点表のDB生成からcomplete未同期までの全行を、復旧用保持有効／無効で分ける | 指定停止点到達後に強制終了 |

- 準備：全行でB0/S0の独立保護コピーを台帳化する。未開始行は直前保存と整理の終結を確認してから制御時計または周期発火の制御を保持し、B1のボード編集を確定する。設定を無効化する製品操作で追加の設定保存を発生させず、保存要求・待機・実行がないことを証拠化する。保存途中行は共通準備後、指定停止点以外を正常に通す。
- 操作・事象：未開始行は「B0/S0成功→保存開始を抑止したままB1へ編集→保存処理なしを確認→クラッシュ／強制終了→再起動→本保存先の正常ファイルを開く」の順に進める。保存途中行は「保存開始→指定到達点の証拠取得→強制終了→再起動→対象保存先を開く」の順。新ZIPが読める行でも利用者選択前の自動採用を観測する。
- 期待結果と根拠：未開始行は最後に成功した本ファイルからB0/view0/S0とA・B画像実体を復元できる。未保存B1や編集履歴の復元は保証対象外とし、その喪失を本行の失敗にしない。保存途中行はB0/S0を失わず、完全completeのないB1/S1を保存成功として自動採用しない。置換後は正常previousを提示し、保持無効でも同じ保護を確認する（[REQ-037の第1受入行と保存途中の受入行](../../product-requirements/non-functional-requirements/cross-cutting/REQ-037-saved-content-durability.md#受入条件)、[DES-041](../non-functional-design/cross-cutting/DES-041-save-integrity-and-recovery.md)）。
- 観測・障害制御：未開始行はB0成功・整理終結、編集後B1と履歴、新保存の要求・待機・実行およびDB／ZIP書出し開始がないこと、本ZIPの終了前後ハッシュ、再開した全保存項目・PNG集合を記録する。保存途中行は停止点、再起動前後の全資料ハッシュ、候補の種類と採用内容を記録する。異常終了に先立つ正常終了・保存・後片付けを制御器が代行しない。
- 後片付け：共通後片付け。事前保護コピー・当該正常候補の証拠を回収してから所有する使い捨て資料だけを整理する。
- 実現方法・準備物：実アプリのクラッシュ相当の異常終了／強制終了と再起動。未開始の期間を維持できる周期制御と保存要求・処理の観測口を後続担当が用意する。固定時間のsleepで保存未開始や指定停止点を代用しない。
- 未決・影響：物理制御口・実ビルド・資料は後続準備未完了。期待する保護を変更する場合は製品設計/要件へ返し、観測不能な行を試験済みとしない。

- 期待結果と根拠：キャッシュ解放後も画像実体が残り、取消と固定済み保存に使える。再表示は保存画像から再生成できる（[REQ-039](../../product-requirements/non-functional-requirements/cross-cutting/REQ-039-image-asset-retention.md)の「Undo・保存からの参照」）。
- 観測・障害制御：Undo/Redo集合、保存保持集合、PNG応答・実描画、保存ZIPのPNGと参照。
- 後片付け：共通後片付け。事前保護コピー・当該正常候補の証拠を回収してから所有する使い捨て資料だけを整理する。
- 実現方法・準備物：実アプリ/PNG/ZIPの結合と代表E2E。
- 未決・影響：物理制御口・実ビルド・資料は後続準備未完了。期待する保護を変更する場合は製品設計/要件へ返し、観測不能な行を試験済みとしない。

### CASE-016

- 確認層／種別・品質観点：結合・E2E／回復資源の保護。
- 前提・環境要件：[共通仕様](#共通のデータ仕様環境要件手順)の実物・段階制御を使用。特記がなければ旧成功B0/S0がある既存保存。旧なしを明示したケースだけ初回仕様を適用する。
- 入力・データ仕様：未完了transactionのprevious、正常.recovery、唯一の正常コピー、稼働中別セッション画像、帰属不明ファイル、不要と確認済みの作業物を同一親に置く。
- 準備：共通準備後、各資料の所有/帰属/参照とハッシュを固定する。復旧候補を選び保存先未確立の状態も作る。
- 操作・事象：不要作業ファイル整理→復旧から開く→別名保存前に再度強制終了→再開。別行で別名保存を成功させる。
- 期待結果と根拠：復元に必要・唯一正常・実行中・帰属不明は削除せず、未参照と確認できた不要物だけ整理対象。元/recoveryは自動修復・上書きせず、別名成功前の再終了でも正常コピーが残る（[REQ-016](../../product-requirements/functional-requirements/cross-cutting/REQ-016-save-failure-recovery.md)・[REQ-039](../../product-requirements/non-functional-requirements/cross-cutting/REQ-039-image-asset-retention.md)、[DES-041](../non-functional-design/cross-cutting/DES-041-save-integrity-and-recovery.md)）。
- 観測・障害制御：資料の事前事後ハッシュ、整理対象、候補帰属、別名出力。
- 後片付け：共通後片付け。事前保護コピー・当該正常候補の証拠を回収してから所有する使い捨て資料だけを整理する。
- 実現方法・準備物：実資料・複数所有状態の結合と復旧E2E。作業先変更操作はDES-049参照。
- 未決・影響：物理制御口・実ビルド・資料は後続準備未完了。期待する保護を変更する場合は製品設計/要件へ返し、観測不能な行を試験済みとしない。

### CASE-017

- 名称・確認目的：成功後の後片付け失敗。
- 対応条件：[COND-001](#cond-001)、[COND-009](#cond-009)。
- 確認層／種別・品質観点：結合／成功と整理の分離。
- 前提・環境要件：[共通仕様](#共通のデータ仕様環境要件手順)の実物・段階制御を使用。特記がなければ旧成功B0/S0がある既存保存。旧なしを明示したケースだけ初回仕様を適用する。
- 入力・データ仕様：complete同期後に不要ZIP/退避削除、prepare削除、complete削除を各別行でアクセス拒否にする。
- 準備：共通準備後、本保存は正常完了でき、整理だけ失敗する条件を分離する。
- 操作・事象：保存成功→整理失敗→未保存表示/通知を確認→再開→正常コピーと残存記録を照合。
- 期待結果と根拠：後片付けだけの失敗で保存成功を巻き戻さず、cleanupPendingとして残存を扱う。completeを最後に削除し、残存不明資料を一括削除しない（[DES-041](../non-functional-design/cross-cutting/DES-041-save-integrity-and-recovery.md)、[DES-008](../data-design/DES-008-project-file-data.md#保存処理の補助ファイル)）。
- 観測・障害制御：成功番号、cleanupPending、削除順、再開内容。
- 後片付け：共通後片付け。事前保護コピー・当該正常候補の証拠を回収してから所有する使い捨て資料だけを整理する。
- 実現方法・準備物：整理I/O差替えと実ACL代表行の結合。
- 未決・影響：物理制御口・実ビルド・資料は後続準備未完了。期待する保護を変更する場合は製品設計/要件へ返し、観測不能な行を試験済みとしない。

### CASE-018

- 名称・確認目的：全保存種類の直前1世代と保持無効。
- 対応条件：[COND-010](#cond-010)。
- 確認層／種別・品質観点：結合／復旧世代。
- 前提・環境要件：[共通仕様](#共通のデータ仕様環境要件手順)の実物・段階制御を使用。特記がなければ旧成功B0/S0がある既存保存。旧なしを明示したケースだけ初回仕様を適用する。
- 入力・データ仕様：B0/view0/S0→設定だけB0/view0/S1→表示位置だけB0/view1/S1を順に成功。view1は中心(128,64)・zoom2、画像・メモ・枠はB0と同じで通常B1の移動・本文変更を含めない。保持有効／無効を別行、初回旧なしの正常空保存を別行にする。
- 準備：既存保存行は共通準備後に保存前本ZIPと既存.recoveryを各回ハッシュ化。初回行は空保存先で旧本ZIP・旧成功基準・.recoveryを作らず、旧なし記録を確認する。
- 操作・事象：各保存をcomplete同期まで完了し、本ZIPと.recoveryを別読込する。
- 期待結果と根拠：保持有効かつ旧ありでは各保存の直前本ZIPが.recovery1世代となる。無効では既存.recoveryを更新/削除せず、初回では架空の復旧用を作らない（[REQ-016](../../product-requirements/functional-requirements/cross-cutting/REQ-016-save-failure-recovery.md)、[DES-008](../data-design/DES-008-project-file-data.md#保存処理の補助ファイル)）。
- 観測・障害制御：各回のold/new/recoveryハッシュと内容、保持固定値、complete。
- 後片付け：共通後片付け。事前保護コピー・当該正常候補の証拠を回収してから所有する使い捨て資料だけを整理する。
- 実現方法・準備物：実ZIP・復旧用更新の結合。設定分離の操作詳細はDES-049参照。
- 未決・影響：物理制御口・実ビルド・資料は後続準備未完了。期待する保護を変更する場合は製品設計/要件へ返し、観測不能な行を試験済みとしない。
