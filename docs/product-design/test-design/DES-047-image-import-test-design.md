## 共通のデータ仕様・環境要件・手順

### 画像データの管理元

本節を画像入力と変換期待値の管理元とする。以下は後続担当が用意するデータの仕様であり、実ファイルの存在・作成済みを意味しない。入力台帳には識別名、形式、符号化寸法、コマ・ページ数、ICCと向き情報、α、バイト数、SHA-256、取得方法を記録する。原本は読み取り専用の保護コピーと試験用複製を分ける。期待寸法・色解釈・先頭画の識別を生成元から決め、対象製品が出した結果を期待画像に転用しない。

| データ群 | 具体的な仕様と代表値 | 判定用途 |
| --- | --- | --- |
| IMG-F | JPEG・PNG・WebP・GIF・TIFF・BMPを各1枚、640×320。左上赤、右上緑、左下青、右下白、中央に形式識別図形。PNG・WebPはα=0/128/255の領域を持つ | 6形式と向き、透過、選択した対象の一致 |
| IMG-M | GIF・WebPは同じ640×320の3コマ（先頭は赤い1、次は緑の2、最後は青い3）。TIFFは640×320の3ページ、同じ識別 | 先頭だけ、動画非再生、残りTIFF未取込通知 |
| IMG-D | 7680×4320→3840×2160、1920×1080→同寸、2160×3840→同寸、4320×4320→2160×2160。追加の技術境界は3841×2160→3840×2159、8000×1→3840×1、1×1→同寸 | REQの寸法例とDESの切捨て・最小1px。各入力は資源上限内であることを別途検査 |
| IMG-C | sRGB・8bit、正常な非sRGB ICC付き、ICCなしRGB、色情報が取得できる別色空間、壊れたICC、16bit RGB(A)。色パッチと半透明輪郭を含み、各入力の色空間を独立に記録 | sRGB・8bit・α、壊れたICCの失敗、線形RGB縮小 |
| IMG-O | 符号化640×320のJPEG/TIFF等に回転・反転を表す向き情報を付けた複製。画素配列はIMG-Fと同じ | 情報を無視した画素向きと情報非引継ぎ |
| IMG-E | ヘッダー切断、途中データ破損、読取権限なしの対応画像、UTF-8テキストを画像風拡張子へ変更した非対応入力 | 形式・読込失敗、対象・理由通知、既存保護 |
| IMG-N | 公開・ログイン不要の試験ページにIMG-Fを置く。通常の画像コピー・ドラッグが可能なページと、URLだけを渡す入力用の制御ページを分ける | Chrome/Edge実物経路とDES URL取得の再現 |

変換寸法は[DES-010の式](../functional-design/collection/DES-010-image-import-pipeline.md#変換寸法派生画像の共通ルール)から独立に算出する。本PNGに対する派生の期待寸法は、長辺256/1024、拡大なし、各辺切捨て・最小1px。本画像128×64なら両派生は本画像と同寸法を共有、512×256なら256×128と本画像、3840×2160なら256×144と1024×576とする。固定sRGB・8bit・非縮小入力の既知画素とα=0/128/255、出力bit深度・方向・寸法は生成元の独立期待値で判定する。REQ-002は数値色誤差の閾値を要求していない。異なるICC色変換の数値比較や縮小半透明輪郭の比較方法が未確定な部分だけを残件とし、CASE-005/013/014の他の判定まで保留しない。無根拠の許容差を追加しない。

### ボード・配置データ

ボードデータの共通仕様は[DES-048](DES-048-board-interaction-test-design.md#共通のデータ仕様環境要件手順)を参照する。本書の基準ボードI0は、既存画像E（中心(-1000,-1000)、100×100、角度0、倍率1）、本文「既存」のメモ、空グループを配置し、要素数・全属性・重なり順・所属を保存前後に採取できる状態とする。取込位置と衝突試験では該当ケースに示す要素だけを原点周辺へ置く。

初期配置の設計期待値は長辺320以下、セル320×320・間隔24、列数`min(N,max(1,ceil(sqrt(N*a))))`、行数`ceil(N/列数)`。受付時の件数N、表示領域縦横比a、中心と倍率、入力順、セル中心を証拠へ記録する。画面表示と保存PNGの寸法を別々に観測する。

### 環境・観測・障害制御

- 製品受入：Windows 11、対象ビルド、同梱固定WebView2、通常利用者権限。Chrome・Edgeは受入開始時点の安定版の実物を使い、名と版を記録する。OSダイアログ、実クリップボード、実HTML5ドロップ、実変換エンジンを確認する。
- 技術契約：入力取得・配置のユニット/フロントエンド結合、ImageMagick 7 Q16・LCMS・6コーデックを使うRust結合、Windows Job Objectを使う実物結合。低層ダブルの成立を実ブラウザ・実変換の成立へ置き換えない。
- 必要な観測：入力識別と順、取得開始終結、変換開始終結・PID・失敗分類、PNGの寸法・色/α/向き情報・SHA-256、登録assetId、配置候補/再検査、画面モデル、実描画と操作可否、取込通知、参照集合。通知だけでPNG生成・表示成功を判定しない。
- 必要な制御：入力イベント終了、HTTP応答・接続/取得時計、変換時計、ワーカー停止/異常終了/メモリ不足、Job Object登録失敗、作業領域書込み失敗、配置候補応答と追加直前の順序、表示失敗。これらは準備すべき仕様であり、既存の試験フックの名称や実装済み能力を仮定しない。
- 準備：使い捨て作業領域と保存先、I0、独立期待値・入力台帳を用意し、初期ボード/原本ハッシュと所有を記録する。障害は当該使い捨て領域だけへ適用する。
- 共通後片付け：終端と所有を確認し証拠を回収、障害を解除、HTTP/クリップボード/ブラウザの試験状態を戻し、通常終了する。未完了処理や唯一の正常画像、帰属不明の復旧候補を削除しない。後片付けの製品契約はDES-050/052を参照する。
- 実行準備残件：ビルド・依存版、実データ、公開ページ、ドライバー/自動化の成立、観測・制御手段、色評価証拠を実装・検証担当が用意する。時計の分解能と測定誤差を記録するが、120秒を延長する許容値へ変えない。

## テスト条件

### COND-001

- 名称・確認対象：全取込経路と取消・既存保護。
- 根拠：REQ-001受入条件のローカル両経路、単一/複数選択、取消、Chrome/Edge各2経路。
- 区分：正常。確認層／種別・品質観点：実機/E2E、機能・入力互換性。
- 技法・網羅対象・理由：経路×形式、ブラウザ×操作の決定表。経路固有の取得不能と選択結果の取り違えを見落とさない。
- 優先理由：全画像利用の入口。観測・制御の見通し：OS選択/コピー/ドラッグと前後モデル・表示を対応付ける。
- 対応ケース：[CASE-001](#case-001)、[CASE-002](#case-002)、[CASE-003](#case-003)。未決・影響：実物版とページは後続準備、契約の期待値は確定。

### COND-002

- 名称・確認対象：6形式、先頭静止画/ページ、保存後の変換属性。
- 根拠：REQ-002の全受入条件。
- 区分：正常。確認層／種別・品質観点：変換結合＋実機/E2E、機能・画像互換性・データ整合性。
- 技法・網羅対象・理由：形式同値分割、寸法の例/境界、異なるコマ識別。先頭画だけを得たことと動画が動かないことを分ける。
- 優先理由：入力の意味を誤って保持しない。観測・制御の見通し：原本、生成PNG、再開後PNG・実表示の三点を照合する。
- 対応ケース：[CASE-003](#case-003)～[CASE-005](#case-005)、[CASE-014](#case-014)。未決・影響：異なるICCの数値比較・縮小透過輪郭の評価方法だけを残件とする。固定sRGB入力の既知画素/α・bit深度、構造・寸法・方向は独立に判定可能。数値色誤差の閾値をREQへ追加しない。

### COND-003

- 名称・確認対象：混在失敗・全失敗、変換打切りと後続継続。
- 根拠：REQ-003全受入条件、REQ-034受入条件。
- 区分：正常/異常をパラメータで区別。確認層／種別・品質観点：ユニット・変換結合・E2E、機能・回復・時間制限。
- 技法・網羅対象・理由：正常/失敗位置の同値分割、期限境界、失敗→次対象の状態遷移。処理順と失敗理由を対応付ける。
- 優先理由：正常分と原本を失うリスク。観測・制御の見通し：ワーカー/成果/通知/後続の終端を観測し無限再試行を除外する。
- 対応ケース：[CASE-006](#case-006)～[CASE-008](#case-008)、[CASE-010](#case-010)、[CASE-012](#case-012)、[CASE-013](#case-013)、[CASE-018](#case-018)。未決・影響：通知の意味は確定、詳細分類・表示文言の製品設計確定は残件。

### COND-004

- 名称・確認対象：利用上限と作業領域書込み失敗時の保護。
- 根拠：REQ-001超過入力、REQ-003作業領域モーダル、DES-010入力固定。
- 区分：異常。確認層／種別・品質観点：Rust結合・実機/E2E、容量・回復。
- 技法・網羅対象・理由：上限の直前/一致/超過×入口、入出力書込み失敗段階。値・構造の管理元はDES-052。
- 優先理由：巨大入力と書込み失敗で旧状態を壊さない。観測・制御の見通し：現物サイズ、実検査、旧モデル・ファイルの保持。
- 対応ケース：[CASE-009](#case-009)、[CASE-010](#case-010)。未決・影響：実障害制御は後続準備。上限内を必ず成功とする保証は追加しない。

### COND-005

- 名称・確認対象：イベント中入力保持、直接画像優先、URL自動取得の制限。
- 根拠：DES-010「入力取得」。REQへの差分反映待ちを含む技術契約。
