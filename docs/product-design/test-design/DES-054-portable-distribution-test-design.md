# DES-054：Windows向けポータブル配布のテスト設計

- 設計状態：評価待ち。配布成立の条件とケースの文書設計。REQ-020の上流反映・レビュー、具体配布物と実環境の準備、実機試験は未完了。残件の担当・解消条件・進行範囲は本文の未決事項・引継ぎに従い、必要な確認後にドラフトへ戻して再レビューする。
- 目的・範囲：初期版の一般利用者によるZIP展開・起動、全同梱資材、固定WebView2、6形式取込・編集・保存・再開、配布資材の更新時保護を具体化する。
- 入力確認日：2026-10-13。
- 根拠・参照要件：[REQ-020](../../product-requirements/non-functional-requirements/cross-cutting/REQ-020-portable-windows-app.md)は条件付き合意。対応範囲と受入案は[DES-012](../non-functional-design/cross-cutting/DES-012-portable-runtime-distribution.md)の配布方針・上流変更案を参照する。
- 選択済みの対象：Windows 11 Home・x64、Microsoftがサポート中の通常リリース、WebView2は常に固定版を同梱。これを未回答として再質問しない。具体OSリリース／ビルド・同梱版・配布ハッシュを受入開始時に固定する準備と、上流本文・受入条件への反映待ちを分ける。
- 依存設計・方針：[DES-012](../non-functional-design/cross-cutting/DES-012-portable-runtime-distribution.md)、[DES-009](../functional-design/cross-cutting/DES-009-project-persistence-recovery.md)、[DES-010](../functional-design/collection/DES-010-image-import-pipeline.md)、[DES-013](../test-strategy/DES-013-common-test-strategy.md)、[ADR-015](../architecture-decisions/2026-10-08-ADR-015-fixed-webview2-distribution.md)（提案）。配布方式の記録をADR採用・成立検証済みへ変えない。
- 分担：6形式・入力の正しさは047、画面・メモ・最小寸法は048、保存・別PC・フォント差・作業先は049、段階障害・画像実体・唯一正常コピーは050、通信は051、容量は052、時間性能は053が主ケース。本書は実配布物で成立する境界を確認する。
- 初期対象外：ARM64、Sモード、Insider、サポート終了リリース、ネットワーク共有から直接起動。単一exeやUSBでの運用を前提にせず、ローカルへ展開した一つの配布フォルダーを対象とする。

## 共通のデータ仕様・環境要件・手順

### 配布物・台帳・利用者データ

| 資料 | 内容・固定項目・取得方法 |
| --- | --- |
| 正常Build-A | 一つの配布ZIPと展開フォルダー。アプリ、画像worker、ImageMagick・codec・Little CMSの必要資材、固定WebView2・loader、ライセンス。ビルド担当が具体版・x64・各相対パス・SHA-256・生成条件を台帳へ記録 |
| 正常Build-B | 更新確認用の別配布物。同じ現形式1／DB1対応を前提に版・ハッシュ・生成条件を別台帳へ固定。具体ビルド番号を本書で捏造しない |
| 異常配布コピー | Build-Aの使い捨てコピーから必要資材1つを欠落、または明らかな異アーキテクチャ等へ変異。変異相対パス・依存機能・ハッシュを記録し正常配布を保護 |
| 6形式入力 | JPEG/PNG/WebP/GIF/TIFF/BMP各1、基本640×360。写真・イラスト、透過PNG、先頭コマ／ページ対照は[DES-047の共通仕様](DES-047-image-import-test-design.md#共通のデータ仕様環境要件手順)へ従う。形式・寸法・元SHA・期待PNGを台帳化 |
| 正常保存P0 | 実体A/B・画像配置・グループ・メモ・表示位置を持つ形式1／DB1の正常ボードと、独立したconfigの共通設定。保存項目は[DES-049](DES-049-persistence-workflow-test-design.md#共通のデータ仕様環境要件手順)、画像保持は[DES-050](DES-050-save-integrity-recovery-test-design.md#共通のデータ仕様環境要件手順)へ従う |

| 実パス対照 | 展開先名「配布 確認/App A」、別CWD名「別 作業」、書込不可の配布先、同名別エンジンがある試験PATH。絶対パスは使い捨ての検証担当所有領域へ確定 |

台帳は具体版を識別する準備資料であり、新しい製品ファイル形式ではない。台帳照合からアプリに自己署名検証・全ファイルハッシュ検査・自動更新という機能を追加しない。固定WebView2・エンジン・codec・SQLite等のセキュリティ更新は配布物の保守責任として同台帳へ記録し、最新という文字列だけを更新準備としない。

### 環境と実物・自動化の境界

- 対象実機／VM：Windows 11 Home・x64のサポート中通常リリース。具体リリース／ビルドとサポート状態は検証担当が受入開始時に公式情報へ照合して固定する。今後のサポート状態を現在の文書検査で保証しない。
- 起動・主要操作は一般利用者権限。環境準備でACLや使い捨てVMを作ることと、製品利用時に管理者昇格を求めないことを区別する。
- 追加アプリ用ランタイム未導入の環境を用意し、Windows標準・端末既存ソフトの一覧を記録。Evergreen未導入／導入済みは使い捨て環境で分け、同梱固定版の実ロードを確認する。
- LocalAppDataのWebView2専用user dataは書込可能。画像作業先・共通設定・保存先はDES-009／049の検査と所有へ従う。配布先に書込できない対照でも他の正規書込先は正常とする。
- 実Tauri・実固定WebView2／loader・実画像worker・codec・Little CMS・SQLite・ZIP・Canvas／WebGL・日本語IMEを使う。Unit・モック・開発用ローダーだけでは配布成立を判定しない。
- E2E自動化は[ADR-009](../architecture-decisions/2026-09-29-ADR-009-test-automation.md)の採用済み方針へ従う。tauri-driver・Edge WebDriver等の具体版と固定ランタイムとの接続は後続準備。driverを製品の必要同梱資材へ追加しない。OSダイアログ・IME・実ロード・画面は手動証拠を組み合わせる。

### 観測・障害制御

配布ZIP・全資材の版／ハッシュ／相対パス、起動exe・CWD／試験PATH、実ロードしたworker・画像エンジン・固定ランタイムの版とパス、user data・共通設定・画像作業先・保存先、実画面／IME／フォーカスと機能内容、保存transaction／complete／本ZIPを関連付ける。具体OSロード情報・アプリ診断・画面取得の口を実装・検証担当が準備し、既存フックを仮定しない。

異常資材は配布コピーだけに適用し、起動／対象機能初期化失敗を識別する。起動しないことを全て同じ形式のアプリエラー通知へ補作せず、OSローダー側の失敗も証拠として扱う。実配布にない依存をPATHやEvergreenで補って成功にしない。入力・保存原本へ障害変異を混ぜない。

### 共通の準備と後片付け

準備は対象OS・一般利用者・依存導入状況を台帳化、正常配布と各資材を照合、配布外利用者データを独立保護、使い捨て展開先・正規書込先を用意、観測口・異常コピーを確認する順とする。既存端末の共有ランタイム・永続PATHを検証のため無断変更しない。

後片付けは失敗した起動／取込／保存を終端または記録付き停止にし、アプリとworkerの終了・所有解放を確認、資材／パス／画面／データの前後証拠を回収、試験プロセス環境や使い捨てACL・配布変異を戻す。唯一の正常コピーと未完了記録は証拠回収前に消さない。検証担当が所有する使い捨てコピーだけを整理し、更新手順の資材置換にデータ削除を混ぜない。
