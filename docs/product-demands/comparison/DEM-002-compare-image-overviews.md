# DEM-002：多くの画像を見渡し全体と細部を比較する

多数の画像を見渡してグループ分けし、分類の理由や意味を残す利用目的は [DEM-003](../organization/DEM-003-organize-image-insights.md#dem-003画像の関係や気づきを自分なりに整理する) を参照する。

- 対象者・状況：利用者が蓄積した多数の参考画像をPCで眺め、気になる画像のまとまりや細部を比較する。参考となる複数画像を並べたいときはペイントアプリの参照用キャンバスを使い、制作用キャンバスと並べて確認する。制作物を操作している間には、1〜2枚程度の参考画像に集中して細部を照合する。
- 対象範囲・対象外：単一ボードでの俯瞰と比較、および制作中の参考画像と制作物の照合を初期対象とする。複数ボードは構想で未選択のため今回の対象外。制作物の品質や着想への効果、市場・収益評価は初期評価の対象外。市場・収益評価はユーザー向け有用性の判断に必須ではない。
- 課題：現在のキャンバスでは画像以外の表示が場所を取り、一度に見渡せる画像が少ない。全体を収めると比較したい特徴が見えにくく、拡大・縮小や移動を繰り返すため画像同士を比べにくい。ペイントアプリケーションで参照用・制作用のキャンバスを2つ開く場合は、片方がバックグラウンドへ回る。ユーザーの説明では、並べたペイントアプリのうちフォーカスが当たった側が前面になり、参照側が隠れる。制作中に参考画像を見比べられず、キャンバスを切り替える必要がある。発生頻度・負担の程度は未確認。
- 望む成果：多くの画像を見渡し、全体と細部を行き来しながら、現在より比較しやすいとユーザーが感じられる。制作物を操作している間も参考画像を見て照合できる。
- 理由・価値：見渡せる範囲の狭さを解消することがユーザーの最優先。制作中に参考画像が隠れて見比べられない困難にも初期版で対応する。制作で試したい表現・構成を見つけることは長期の期待であり、初期評価の条件にしない。
- 根拠・出典：[構想](../../product-ideas/reference-board/IDEA-001-reference-board.md#着想の背景と根拠)、[初期評価の範囲](../product-decisions/2026-09-11-initial-evaluation.md#決定内容)、[背景・利用状況](#背景利用状況)、[制作中の参照を初期対象とする判断](../product-decisions/2026-09-12-initial-reference-during-creation.md#決定内容)、[初期5要求の範囲と優先度](../product-decisions/2026-09-13-final-demand-agreement.md#決定内容)。構想の意向・利用状況と、各判断記録の決定内容・適用範囲を参照する。
- 優先度・理由：必須。ユーザーが最優先とする見渡し・比較の改善を直接扱う。
- 成功指標：普段の制作で試し、困った点が解消したかを振り返る。多くの画像を見渡し、制作中には参考画像の細部を見比べられることを実際に試し、ユーザーが十分に役立つと判断できることを初期版の達成目安とする。数値目標は初期判断に必須としない。評価期間は試せる段階で決める（[初期版の達成目安と評価方法の判断](../product-decisions/2026-09-13-initial-success-criteria.md#決定内容)）。有用性は未検証。制作物の品質・創造性向上は初期条件に含めない。
- 合意状況：合意済み
- 関連要求：[DEM-001](../collection/DEM-001-collect-reference-images.md)、[DEM-003](../organization/DEM-003-organize-image-insights.md)、[DEM-004](../cross-cutting/DEM-004-resume-saved-work.md)・[DEM-005](../cross-cutting/DEM-005-continue-on-another-pc.md)。
- 未決事項・仮定：評価期間は実際に試せる段階で判断する。達成目安は成功指標のとおりで、数値目標の設定は初期判断の前提としない。制作環境はモニター1台で画像表示アプリとペイントアプリを半分ずつ表示し、ペイントアプリ内で参照用・制作用の2キャンバスを開く場合に片方が背後へ回るというユーザーの申告がある。参照用キャンバスを使う理由は複数参考画像を並べて確認するためと確認できた。フォーカス側が前面になることが参照側の隠れる理由というユーザー説明を得た。現在の画像表示アプリの不足、解像度は未確認。画像表示アプリが複数画像を表示できないと断定しない。表示方向・固定分割・製品の表示仕様は未指定である。同じPC・画面・画像群で現行手段と比較する方法は既定の評価方法としない。参考画像が隠れる支障の発生頻度・負担の程度は未確認。制作中の参照を実現する方式は未指定で、要件定義担当へ引き継ぐ。制作物の品質や着想への効果は未検証で、後の評価に委ねる。複数画像の比較が制作の発見につながることは未検証仮説。外部調査は未実施であり、市場・競合について確認済み事実はない。振り返りで比較と整理の観点を分けて見ることは提案。

## 背景・利用状況

ユーザーはフォルダー・画像ビューアに加えてペイントアプリのキャンバスに画像を並べるが、ツールバー・パネルが場所を取り、一度に見渡せる画像が少ないという利用状況の申告がある（[初期評価の範囲](../product-decisions/2026-09-11-initial-evaluation.md)）。実画面の観察・比較数の実測は未実施。

利用状況の申告：Photoshopなどのペイントアプリのキャンバスを利用する。表示領域が狭く、全体を収めると特徴が見えにくくなり、拡縮や移動を繰り返す比較が難しい。制作中は参考画像用と制作用のキャンバスを切り替える必要があり、参考画像用が背後へ回ると見比べられない。観察・実測による確認ではない。

制作中は細部に集中し、1〜2枚程度の参考画像を見比べる利用意向がある。数百枚程度を蓄積・俯瞰する場面と、制作中に少数の画像の細部へ集中する場面を区別する。1〜2枚はこの利用場面の目安であり、表示上限や固定枚数の指定ではない。

普段の制作環境はモニター1台で、画像表示アプリケーションとペイントアプリケーションを画面の半分ずつに表示する。場合によってはペイントアプリケーションで参照用・制作用のキャンバスを2つ開き、その場合は片方がバックグラウンドへ回る。利用状況の申告であり、実画面の観察ではない。半分ずつの表示方向は未指定。

参考となる複数の画像を並べて確認するため、参照用キャンバスを使う。参考画像を並べたペイントアプリのキャンバスと制作用のキャンバスを並べる。申告された環境ではフォーカス側が前面になり、参照側が隠れる。利用状況の申告として扱い、OSや各アプリの一般仕様を検証したものではない。
