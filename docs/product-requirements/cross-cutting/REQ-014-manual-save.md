# REQ-014：手動保存

- 種類：機能
- 参照要求：[DEM-004](../../product-demands/cross-cutting/DEM-004-resume-saved-work.md#dem-004蓄積内容を保ち後日再開する)
- 参照時点の要求：DEM-004「画像・配置・グループ・メモを保ち後日再開する」。参照要求はいずれも合意済み。
- 内容：利用者の保存操作で現在の内容を保存できる。定期保存・設定保存中も手動保存を受け付け、少なくとも操作時点までの確定済み変更を保存してから完了を通知する。
- 適用条件：利用者のWindows 11初期版での単一ボードの利用。
- 業務ルール・例外：自動保存の有効・無効に依存しない。新しい保存内容が古い内容で置き換わらないことを保証する。操作後に加えた変更が残る場合は、保存完了と未保存状態を区別して示す。 メモ入力中は入力済み文章を確定して保存し、そのまま入力を続けられる。IME変換中の部分は保存対象から除外し、確定済み部分の保存完了と変換中内容の未保存を区別して示す。編集取消の基点は保存対象として確定した文章へ進む。保存失敗でも文章は未保存のまま保持する。画像配置のドラッグ中も確定済み内容を保存対象とし、ドラッグ完了を待たない。途中配置を保存済みと表示しない。手動保存には最新のボード・表示位置・設定を含める。設定だけの保存で手動保存要求を満たした扱いにしない。
- 追加ルール：[利用上限](REQ-029-image-and-project-limits.md#画像とプロジェクトの利用上限)と作業・保存領域の容量を確認する。超過や書込み失敗で成功を通知せず、現在の編集内容を保持する。
- セッション決定の反映：配置ドラッグ中も手動保存を受け付け、確定済み内容を保存対象とする。ドラッグ終了を待つことを受付条件にせず、ドラッグを継続できる。未確定の配置は開始前の値を用い、後で確定した配置は後続変更として扱う。保存要求は既存の直列化に従う。前面化とドラッグは[編集共通ルール](../organization/REQ-027-edit-history-and-stacking.md#編集履歴と重なり順の共通ルール)に従い、途中保存は開始前の順序・位置・枠を使用する。
- 反映根拠：本セッションのユーザーの回答と未反映事項の整理計画の反映指示。決定済み方針と変更後要件全体の合意を区別する。
- 保存・排他共通ルール：[同一ファイル利用と保存再試行](REQ-032-file-lock-and-save-retry.md#同一ファイル利用と保存再試行の共通ルール)を適用する。
- 今回の反映根拠：ユーザーのセッション決定と要件反映計画実行指示。[設定と再開の判断](../../product-demands/product-decisions/2026-10-06-project-settings-and-font-resumption.md#決定内容)および[同一ファイル利用と再試行の判断](../../product-demands/product-decisions/2026-10-06-project-lock-and-save-retry.md#決定内容)の決定内容に基づく反映。技術方式の採用、REQ全体の合意、実機試験は区別する。
- 優先度・理由：必須。画像・配置・グループ・メモを保ち後日再開するという初期成果を、今回回答された手動保存の振る舞い・条件で満たすため。
- 根拠・出典：上記参照要求、[現行5要求への合意](../../product-demands/product-decisions/2026-09-13-final-demand-agreement.md#決定内容)、今回の要件定義対話でのユーザーの回答（親エージェント経由の要約）。 未決事項インタビューにおけるユーザーの回答：自動保存中も手動保存を受け付け、操作時点までの保存を保証する。内部処理順・競合防止方式は設計へスキップする。 現在の根拠：ユーザーの保存方式に関する個別回答と「保存処理の統合と、異常終了後の復元設計」の実行指示。合意済み本文を変更したため現在はドラフト。個別の方針決定と変更後REQ全体の合意・試験合格は区別する。
- 変更根拠：ユーザーの計画実行指示。意味・受入条件の変更によりドラフトとし、従前の合意を変更後本文への合意とはしない。
- 合意状況：ドラフト
- 依存要件：[REQ-011](REQ-011-restore-saved-content.md#req-011保存内容の復元)、[REQ-015](REQ-015-save-status.md#req-015保存状態の識別)、[REQ-016](REQ-016-save-failure-recovery.md#req-016保存失敗時の内容保護と再試行)
- 未決事項：保存・排他・再試行と本項の振る舞いは具体化済み。変更後本文・受入条件は合意レビュー待ち。設計担当は実装引継ぎ前に要件との一致・ライブラリ選定を確認し、検証担当は受入実施前に保存障害・異常終了・外部変更・設定分離と該当する入力境界の成立を確認する。解消条件は本項・共通受入条件の成立。技術選定と具体的試験手順は設計・検証側に保持する。

### 受入条件

| ケース | 前提 | 操作・事象 | 期待結果 |
| --- | --- | --- | --- |
| 正常 | 未保存の変更がある | 自動保存有効時・無効時それぞれで手動保存する | 変更が保存され、保存完了を確認できる |
| 正常 | 自動保存中にさらに編集し、未保存変更がある | 手動保存を実行する | 操作を受け付け、少なくとも手動保存操作時点までの確定済み内容（IME変換中部分を除く）を保存してから完了を知らせる。古い保存処理で新しい保存内容が置き換わらない |
| 正常 | 手動保存を受け付けた後にも編集を行い、その変更が保存対象に含まれていない | 手動保存が完了する | 保存操作時点までの内容の完了を知らせ、後続の変更は未保存であると分かる |
| 正常 | メモ文章を入力中である | 手動保存する | 入力済み文章を保存し、そのまま入力を継続できる。編集取消の基点は保存対象として確定した文章へ進む |
| 正常 | メモにIME変換中の部分がある | 手動保存する | 変換中部分を除いた確定済み文章を保存し、変換中内容は未保存と分かる。変換を強制確定しない |
| 正常 | 設定保存中に未保存の画像移動がある | 手動保存し、さらに設定を変更する | 手動操作時点までの確定内容を保存してから完了通知する。後続変更を保存済みと誤認させず、先行設定保存で画像内容を巻き戻さない |
| 異常 | 出力ZIPが33GiB超過または作業・保存先が容量不足 | 保存する | 本ファイルの置換前に超過を検出して成功を通知せず、編集内容を保持する |
| 正常 | 重なり順を変更しない配置ドラッグ中で、他に確定済みの未保存変更がある | 手動保存する | ドラッグ終了を待たず保存対象を受け付け、途中配置を除いた確定内容を保存する。ドラッグを継続できる |
| 正常 | ドラッグ中の保存対象が固定されている | ドラッグを終了して配置を確定する | 確定後の配置を当該保存の成功だけで保存済みにせず、後続変更として残す |
| 正常 | 前面化を伴う移動中 | 手動保存してから解放／取消する | 開始前の位置・順序・枠を保存し操作継続可能。解放の確定は後続未保存、取消は開始前へ戻す |
| 異常 | 置換後失敗で書込停止中 | 保存・明示再試行をする | 新保存で失敗記録を飛ばさず、中断処理の照合・完了後に後続保存する。不一致なら別名保存可能 |
