# REQ-019：利用者の別PCへの引継ぎ

- 種類：機能
- 参照要求：[DEM-005](../../product-demands/cross-cutting/DEM-005-continue-on-another-pc.md#dem-005別pcでも蓄積内容を使い続ける)
- 参照時点の要求：DEM-005「同じ4種の内容を利用者の別PCへ引き継ぎ続きを進める」。参照要求はいずれも合意済み。
- 内容：利用者が最新の保存内容を別PCに移し、画像・配置・グループ・メモを引き継いで収集・比較・整理を続けられる。
- 適用条件：利用者のWindows 11初期版での別PCへの継続利用。保存内容の切替時の保護・選び直しは、同一PC内で保存内容を開き直す場合にも適用する。
- 業務ルール・例外：ユーザーが片方ずつ使用する。自動同期・他者共有は今回の対象ではない。移送元の保存内容を保持する。読み込めない移送内容は開かず対象と理由を通知し、現在のボードを保護する。正常な内容を再移送して開ける。別の保存内容への切替前に未保存変更がある場合は、保存・破棄・キャンセルを選べる。保存失敗時は現在の内容を保持し、切替を中止する。開くだけでは既存の保存内容を上書きせず、誤選択に気づいたら別の保存内容を選び直せる。 保存・設定・表示位置の範囲と未保存保護はREQ-011～017に従う。同一PCで同じファイルを開き直す場合も保存・破棄・キャンセルを選べ、保存を選んだ場合は保存完了後の最新内容を読み直す。保存前の読込候補へ戻さない。取込中の切替は完了を待ち、確認中の新たな定期保存・設定保存は開始しない。キャンセル時の再開はREQ-012・017に従う。
- セッション決定の反映：最新内容の保存成功を確認し、移送元プロジェクトを閉じてから、単一の.refboardファイルをOSでコピーする。保存・終了失敗や終了取消時は移送準備完了と案内しない。開いたままのファイルの安定したコピー提供は初版の操作手順にしない。アプリはOSコピーの成功を自動判定しない。
- 反映根拠：本セッションのユーザーの回答と未反映事項の整理計画の反映指示。決定済み方針と変更後要件全体の合意を区別する。
- 保存・排他共通ルール：[同一ファイル利用と保存再試行](REQ-032-file-lock-and-save-retry.md#同一ファイル利用と保存再試行の共通ルール)を適用する。
- 今回の反映根拠：ユーザーのセッション決定と要件反映計画実行指示。[設定と再開の判断](../../product-demands/product-decisions/2026-10-06-project-settings-and-font-resumption.md#決定内容)および[同一ファイル利用と再試行の判断](../../product-demands/product-decisions/2026-10-06-project-lock-and-save-retry.md#決定内容)の決定内容に基づく反映。技術方式の採用、REQ全体の合意、実機試験は区別する。
- 設定共通ルール：[設定の保存・失敗・適用範囲](REQ-030-shared-settings.md#設定の共通ルール)に従う。
- 再開調整ルール：[フォント差による再開調整](REQ-031-font-resumption-adjustments.md#フォント差による再開調整の共通ルール)を適用する。
- 優先度・理由：必須。同じ4種の内容を利用者の別PCへ引き継ぎ続きを進めるという初期成果を、今回回答された利用者の別PCへの引継ぎの振る舞い・条件で満たすため。
- 根拠・出典：上記参照要求、[現行5要求への合意](../../product-demands/product-decisions/2026-09-13-final-demand-agreement.md#決定内容)、今回の要件定義対話でのユーザーの回答（親エージェント経由の要約）。 未決事項インタビューにおけるユーザーの回答：メモの所属と相対配置も別PCへ引き継ぐ。移送元と現在の内容を保護して再移送・選び直しを可能にし、切替前の未保存変更を扱う。移送形式は設計へスキップする。 現在の根拠：ユーザーの保存方式に関する個別回答と「保存処理の統合と、異常終了後の復元設計」の実行指示。合意済み本文を変更したため現在はドラフト。個別の方針決定と変更後REQ全体の合意・試験合格は区別する。
- 合意状況：ドラフト
- 依存要件：[REQ-011](REQ-011-restore-saved-content.md#req-011保存内容の復元)、[REQ-014](REQ-014-manual-save.md#req-014手動保存)、[REQ-016](REQ-016-save-failure-recovery.md#req-016保存失敗時の内容保護と再試行)、[REQ-020](REQ-020-portable-windows-app.md#req-020windows-11でのインストール不要利用)
- 未決事項：保存・排他・再試行と本項の振る舞いは具体化済み。変更後本文・受入条件は合意レビュー待ち。設計担当は実装引継ぎ前に要件との一致・ライブラリ選定を確認し、検証担当は受入実施前に保存障害・異常終了・外部変更・設定分離と該当する入力境界の成立を確認する。解消条件は本項・共通受入条件の成立。技術選定と具体的試験手順は設計・検証側に保持する。

### 受入条件

| ケース | 前提 | 操作・事象 | 期待結果 |
| --- | --- | --- | --- |
| 正常 | メインPCで4種の内容を保存完了しプロジェクトを閉じている | 利用者が.refboardをOSでコピーしてサブPCへ移し開く | 画像の位置・回転・表示サイズ、画像・メモの所属と相対配置、未所属メモ、空グループを含む4種の内容が保持され、編集・保存を続けられる |
| 異常 | 別PCへの移送が失敗し、移送先の内容が読めない | 移送先で開こうとし、その後正常な内容を再移送して開く | 読めない対象と理由を通知し、移送元・現在のボードを保持する。再移送後は内容を復元できる |
| 正常 | 現在のボードに未保存変更がある | 別の保存内容を開く際に保存を選ぶ | 現在の変更を保存成功後に切り替える |
| 正常 | 現在のボードに未保存変更がある | 別の保存内容を開く際に破棄を選ぶ | 現在の未保存変更を破棄し、選んだ保存内容へ切り替える。既存の保存内容は上書きしない |
| 正常 | 現在のボードに未保存変更がある | 別の保存内容を開く際にキャンセルする | 切り替えず、編集中の内容を維持する |
| 異常 | 切替前の保存が失敗する条件である | 未保存変更を保存して別の保存内容へ切り替えようとする | 切替を中止し、現在の内容と未保存状態を保持する |
| 異常 | 目的と違う正常な保存内容を選んで開いた | 間違いに気づき、目的の保存内容を開き直す | 開くだけでは既存の保存内容は上書きされず、選び直せる。未保存変更がある場合は保存・破棄・キャンセルを選べる |
| 正常 | 現在のファイルに未保存変更がある | 同じファイルを選び、保存して開く | 保存成功後の内容を読み直し、保存前の古い候補へ戻らない |
| 正常 | 現在のファイルに未保存変更がある | 同じファイルを選び、破棄／キャンセルする | 破棄は保存済み内容を読み直し、キャンセルは現在の編集を保持する |
| 異常 | 最新内容の保存またはプロジェクトを閉じる処理が失敗する | 別PCへの移送を準備する | 成功・準備完了と案内せず、現在の内容を保持する。保存して閉じた後にコピーする手順へ戻れる |
| 正常 | 本文・幅・文字サイズ・グリッド設定・表示中心倍率を保存して閉じた | 別PCへコピーして開く | 保存値を復元し、フォント差の高さ・枠・座標は共通ルールで調整する。PC設定と履歴は移送しない |
| 異常 | 外部変更版へ切替希望で現在編集が未保存 | 外部変更版を開く | 保存・破棄・キャンセルによる保護と候補検証を経る。競合した元への上書き保存をしない |
| 異常 | 再試行・切替保存を待っている | キャンセル後に保存完了が届く | 現在編集を保持し、後着成功で切替を実行しない |
