# REQ-015：保存状態の識別

- 種類：機能
- 参照要求：[DEM-004](../../product-demands/cross-cutting/DEM-004-resume-saved-work.md#dem-004蓄積内容を保ち後日再開する)
- 参照時点の要求：DEM-004「画像・配置・グループ・メモを保ち後日再開する」。参照要求はいずれも合意済み。
- 内容：保存中・保存完了・保存失敗を区別でき、ボード・表示位置と設定それぞれの未保存が分かる。
- 適用条件：利用者のWindows 11初期版での単一ボードの利用。
- 業務ルール・例外：保存失敗を保存完了として扱わない。保存完了後も、その保存に含まれない後続変更があれば未保存状態を示す。 設定の保存中・成功・失敗はボードの保存状態と分ける。設定保存成功だけでボード全体を保存済みにしない。IME変換中・未確定操作がある場合は、確定済み部分が保存済みでも入力中内容が未保存と分かる。処理受付を保存完了と表示しない。成功後の一時ファイル整理だけの失敗は、保存失敗に置き換えず整理保留として区別する。
- 保存・排他共通ルール：[同一ファイル利用と保存再試行](REQ-032-file-lock-and-save-retry.md#同一ファイル利用と保存再試行の共通ルール)を適用する。
- 今回の反映根拠：ユーザーのセッション決定と要件反映計画実行指示。[設定と再開の判断](../../product-demands/product-decisions/2026-10-06-project-settings-and-font-resumption.md#決定内容)および[同一ファイル利用と再試行の判断](../../product-demands/product-decisions/2026-10-06-project-lock-and-save-retry.md#決定内容)の決定内容に基づく反映。技術方式の採用、REQ全体の合意、実機試験は区別する。
- 優先度・理由：必須。画像・配置・グループ・メモを保ち後日再開するという初期成果を、今回回答された保存状態の識別の振る舞い・条件で満たすため。
- 根拠・出典：上記参照要求、[現行5要求への合意](../../product-demands/product-decisions/2026-09-13-final-demand-agreement.md#決定内容)、今回の要件定義対話でのユーザーの回答（親エージェント経由の要約）。 未決事項インタビューにおけるユーザーの回答：手動保存操作以降の変更が残る場合も、完了と未保存を区別して示す。 現在の根拠：ユーザーの保存方式に関する個別回答と「保存処理の統合と、異常終了後の復元設計」の実行指示。合意済み本文を変更したため現在はドラフト。個別の方針決定と変更後REQ全体の合意・試験合格は区別する。
- 合意状況：ドラフト
- 依存要件：[REQ-011](REQ-011-restore-saved-content.md#req-011保存内容の復元)
- 未決事項：保存・排他・再試行と本項の振る舞いは具体化済み。変更後本文・受入条件は合意レビュー待ち。設計担当は実装引継ぎ前に要件との一致・ライブラリ選定を確認し、検証担当は受入実施前に保存障害・異常終了・外部変更・設定分離と該当する入力境界の成立を確認する。解消条件は本項・共通受入条件の成立。技術選定と具体的試験手順は設計・検証側に保持する。

### 受入条件

| ケース | 前提 | 操作・事象 | 期待結果 |
| --- | --- | --- | --- |
| 正常 | 変更がある | 保存を開始し完了する | 保存中と完了を区別できる |
| 異常 | 保存が失敗する条件 | 保存する | 失敗と未保存が分かる |
| 正常 | 保存開始後の変更がその保存に含まれていない | 保存が完了する | 対象の保存が完了したことと、後続変更が未保存であることを識別できる |
| 正常 | ボード変更が未保存で、設定だけ保存に成功する | 状態表示を確認する | 設定保存の成功とボードの未保存を区別できる |
| 異常 | 設定保存だけ失敗する | 状態表示を確認する | 設定保存失敗・未保存と再試行方法が分かり、ボード保存成功を取り消した表示にしない |
| 異常 | 置換後保存失敗・追加入力がある | 明示再試行で中断分が完了する | 中断分の保存済みと後続編集の未保存を区別し、後続を巻き戻したり保存済みと誤表示しない |
| 正常 | フォント差の枠・座標調整が未保存 | 設定だけ保存成功する | 設定成功と調整後ボード未保存を区別する。座標補正通知なしでも未保存状態は識別できる |
