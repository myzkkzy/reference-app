# REQ-016：保存失敗時の内容保護と再試行

- 種類：機能
- 参照要求：[DEM-004](../../product-demands/cross-cutting/DEM-004-resume-saved-work.md#dem-004蓄積内容を保ち後日再開する)
- 参照時点の要求：DEM-004「画像・配置・グループ・メモを保ち後日再開する」。参照要求はいずれも合意済み。
- 内容：ボード保存・設定保存の失敗時は直前の保存成功内容と編集中内容を保持する。アプリ動作中は編集を続け、未保存を確認して再試行できる。
- 適用条件：利用者のWindows 11初期版での単一ボードの利用。
- 業務ルール・例外：アプリのクラッシュ・強制終了後は、保存途中の場合を含め、最後に保存成功した内容まで復元を保証する。未保存変更の復元は保証しない。 保存成功は、本ファイルと必要な復旧用処理の検証および保存完了の記録が完了した時点とする。画面通知前に異常終了しても、この成功内容を復元対象にする。完了記録のない保存途中の新内容を、単に読めるという理由で成功扱いしない。復旧用保持が有効なら設定・表示位置だけを含む全保存で直前1世代を入れ替える。無効でも保存途中の正常内容保護は必要で、既存復旧用は更新・自動削除しない。退避・復旧用を開く場合は利用者の選択後に開き、元ファイルを自動修復せず別名保存する。初回成功前には保証対象の旧保存はない。停電・媒体故障への保証は追加しない。
- 追加ルール：画像作業領域と保存先の容量不足・アクセス拒否をモーダルで通知し、保存せず、別の場所へ自動切替しない。表示キャッシュを解放しても保存・Undo・復元に必要な画像を保持する。
- 保存・排他共通ルール：[同一ファイル利用と保存再試行](REQ-032-file-lock-and-save-retry.md#同一ファイル利用と保存再試行の共通ルール)を適用する。
- 今回の反映根拠：ユーザーのセッション決定と要件反映計画実行指示。[設定と再開の判断](../../product-demands/product-decisions/2026-10-06-project-settings-and-font-resumption.md#決定内容)および[同一ファイル利用と再試行の判断](../../product-demands/product-decisions/2026-10-06-project-lock-and-save-retry.md#決定内容)の決定内容に基づく反映。技術方式の採用、REQ全体の合意、実機試験は区別する。
- 設定共通ルール：[設定の保存・失敗・適用範囲](REQ-030-shared-settings.md#設定の共通ルール)に従う。
- 優先度・理由：必須。画像・配置・グループ・メモを保ち後日再開するという初期成果を、今回回答された保存失敗時の内容保護と再試行の振る舞い・条件で満たすため。
- 根拠・出典：上記参照要求、[現行5要求への合意](../../product-demands/product-decisions/2026-09-13-final-demand-agreement.md#決定内容)、今回の要件定義対話でのユーザーの回答（親エージェント経由の要約）。 未決事項インタビューにおけるユーザーの回答：異常終了後は最後に保存成功した内容まで保証し、未保存変更の復元は保証しない。失敗の再現手順は設計・検証へスキップする。 現在の根拠：ユーザーの保存方式に関する個別回答と「保存処理の統合と、異常終了後の復元設計」の実行指示。合意済み本文を変更したため現在はドラフト。個別の方針決定と変更後REQ全体の合意・試験合格は区別する。
- 変更根拠：ユーザーの計画実行指示。意味・受入条件の変更によりドラフトとし、従前の合意を変更後本文への合意とはしない。
- 合意状況：ドラフト
- 依存要件：[REQ-011](REQ-011-restore-saved-content.md#req-011保存内容の復元)、[REQ-015](REQ-015-save-status.md#req-015保存状態の識別)
- 未決事項：保存失敗後の振る舞い・復元保証範囲は具体化済み。設計担当は実装引継ぎ前にライブラリ・排他／再試行契約を確認し、検証担当は検証計画時に障害・異常終了の再現手順を固定し、受入実施前に本項・共通条件の成立を確認する。変更後REQの合意レビューと技術検証待ちであり、未実施の試験を合格としない。

### 受入条件

| ケース | 前提 | 操作・事象 | 期待結果 |
| --- | --- | --- | --- |
| 異常 | 保存済み内容に変更を加え、保存失敗を再現できる | 保存を失敗させる | 直前保存内容と編集中内容が保たれ、未保存を確認できる |
| 異常 | 保存失敗後もアプリが動作している | 編集を続け、原因解消後に再試行する | 編集でき、再試行で内容を保存できる |
| 異常 | 保存成功した内容に未保存変更を加えている | アプリをクラッシュ・強制終了させて再開する | 最後に保存成功した内容を復元できる。未保存変更の復元は保証対象外 |
| 異常 | 保存成功した内容に変更を加え、次の保存を実行中である | 保存完了前にアプリを異常終了させて再開する | 直前に保存成功した内容が失われず、復元できる |
| 異常 | 設定だけを保存中である | アプリを強制終了する | 最後に成功したボード・表示位置・設定の組合せが失われず復元できる |
| 異常 | 新ファイルへの置換後だが保存完了記録前である | 強制終了して開き直す | 直前成功内容を退避から提示でき、新しい内容を保存成功として自動採用しない |
| 異常 | 保存完了記録は完了したが画面通知前である | 強制終了して開き直す | 検証済みの新しい保存成功内容を復元する |
| 正常 | 復旧用保持が有効で旧保存がある | 設定だけ／表示位置だけの保存を各々成功させる | 各保存で直前のファイルが復旧用1世代となる |
| 異常 | 復旧用保持が無効で保存途中に異常終了する | 開き直す | 継続保持無効でも最後の保存成功内容を保護する。既存復旧用を無効化だけで削除しない |
| 異常 | 退避・復旧用から内容を開いた | 再保存を試みる | 元ファイルや開いた復旧用を上書きせず別名保存する。保存前の再度の異常終了でも唯一の正常内容が残る |
| 異常 | 作業領域または保存先へ書込み不可 | 取込または保存する | モーダルで理由を通知し、自動で保存先を変更しない。未保存内容・既存正常ファイルを保持する |
| 正常 | 削除画像がUndoまたは保存処理から参照されている | 表示キャッシュを解放する | 画像実体は残り、取消・保存に利用できる |
| 異常 | 本ファイル置換後の保存失敗 | 追加入力後に再試行し、中断内容が一致する | 中断分だけ成功基準に進め、追加入力を保持・未保存として後続保存する |
| 異常 | 外部変更・削除・記録不一致 | 再試行する | 元保存先を上書きせず編集を保持し別名保存できる。外部版の読込には未保存保護を使う |
| 異常 | PC側設定の保存／読込が失敗 | 設定変更または起動する | 保存失敗は旧保存値と入力・再試行を保持。読込失敗は通知して通常既定値。実作業先失敗では自動代替しない |
