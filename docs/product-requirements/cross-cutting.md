# 継続利用と共通品質：要件

## 文脈

画像処理・資源管理・読込制限の計画反映を保持し、セッション決定の設定・再開調整・排他・再試行を反映。意味変更した要件は各項のとおりドラフトとし、従前の合意と区別する。

利用者による収集・比較・整理を保存し、同じ利用者が別PCで再開する。従前の合意はユーザーによる分類指定に基づき、今回変更した要件全体の合意とは区別する。

各要件は要求とユーザーの回答を具体化し、ユーザーが当時の本文・受入条件・優先度（全件必須）と提示した分類に明示的に合意した。現在の合意状況と根拠は各要件に記載する。保存統合のユーザーの回答・計画実行指示を反映したREQ-011～017・019は意味変更に伴いドラフトとし、それ以外の状態は維持する。条件付き合意の未決事項は後続工程へ引き継ぎ、実装完了・試験合格とは区別する。

関連テーマ：[収集](collection.md)、[探索・整理](comparison.md)。共通要件本文は本書だけで管理する。

## 画像とプロジェクトの利用上限

ユーザーの「画像処理・資源管理・読込制限の設計具体化」計画実行指示を反映する。REQ-001～003・008・010・011・014・016に適用し、個別回答・計画反映と変更後要件全体への合意を区別する。

| 対象 | 利用上限 |
| --- | --- |
| 取込元画像 | 1億画素、幅・高さ各32768px、1GiB |
| 保存する内部PNG | 長辺3840px・短辺2160px、1ファイル64MiB |
| プロジェクトのmanifest / DB | 64KiB / 256MiB |
| ZIPエントリー / ボード要素 | 100,002件 / 画像・メモ・グループ合計100,000要素 |
| プロジェクト展開後合計 / 保存ファイル | 32GiB / 33GiB |

KiB・MiB・GiBは2進単位。各上限は境界値を含み、全条件を満たす必要がある。取込・作成・編集・保存にも同じ制限を適用する。500枚は性能評価条件であり登録上限ではない。容量や要素数を超える変更は理由を示して拒否し、既存内容を切り捨てない。保存出力時に判明した超過は保存失敗として現在の編集を保持する。既存ファイルの読込では一部だけ採用せず、現在のボードと入力を保持する。

表示資源が不足した場合は追加処理を止め、現在の編集内容を保持して通知する。低解像度の仮表示だけを細部表示完了とみなさない。通常時・保存中の操作と細部表示、500枚の取込30秒・再開5秒の基準は変更しない。

画像の作業領域は既定でプロジェクトの隣の専用フォルダーとし、アプリ設定で代替先を指定できる。変更の保存・失敗・次回適用は[設定の共通ルール](#設定の共通ルール)に従う。書込不可・容量不足はモーダルで理由を知らせ、自動で別の場所へ切り替えず、保存成功にも扱わない。正常終了時に不要な作業ファイルを削除する。異常終了後の復元に必要な候補は保護する。表示キャッシュの削除でUndo・保存に必要な画像を失わない。

共通の受入条件：

| ケース | 前提 | 操作・事象 | 期待結果 |
| --- | --- | --- | --- |
| 正常 | 作業先設定を変更し現在のボードが開いている | 次のプロジェクトを開く | 現在の作業先は途中移動せず、次回から指定先の専用領域を使う |
| 正常 | 表示キャッシュを解放した画像がある | 再表示する | 保存画像から再生成でき、Undo・保存用の画像を失わない |
| 異常 | 表示用メモリを確保できない | 新たな画像の細部表示を要求する | 追加処理を止めて通知し、現在の編集を保持する。低解像度表示を完了としない |
| 正常 | 正常終了するプロジェクトに不要キャッシュがある | 閉じる | 不要ファイルを整理し、復元に必要な候補を巻き込んで削除しない |

設計の正本：[DES-008](../product-design/data-design/project-file.md#読込保存の資源上限)、[DES-009](../product-design/project-persistence.md#画像処理資源管理)。数値の反映は実測による達成確認ではない。

## 設定の共通ルール

REQ-011・013・016・019と[編集履歴](organization.md#編集履歴と重なり順の共通ルール)に適用する。セッション決定とユーザーの要件反映計画実行指示を反映。設定の保存・読込失敗の具体化は[DES-007](../product-design/screen-design/persistence.md)、[DES-009](../product-design/project-persistence.md)を参照する。

| 区分 | 項目・初期値 | 適用・保存・引継ぎ |
| --- | --- | --- |
| プロジェクト設定 | 自動保存オン、復旧用保持オン、グリッド表示オン、間隔32、スナップオン、回転刻み15度 | 即時適用しボード編集とは独立して保存。同じファイルと利用者の別PCへ引き継ぐ |
| PC側アプリ設定 | ボード履歴上限100（1～1,000）、画像作業先はプロジェクト隣の専用フォルダー | 同じWindowsユーザーの全プロジェクト共通。保存成功値を次回の新規作成・オープン・再オープンから適用。プロジェクトへ含めず別PCへ移送しない |

- プロジェクト設定だけの保存は最後の保存成功内容へ最新設定だけを組み合わせ、未保存の本文・配置・枠・表示や読込時のフォント調整を混入させない。保存失敗でも適用値を維持し、設定の未保存と再試行を示す。設定画面を閉じるだけでは取り消さない。
- PC設定の保存失敗では旧保存値を使用し、入力値と再試行手段を残す。設定がない初回は通常既定値を使う。起動時の設定読込失敗は通知して通常既定値で開始する。設定読込失敗による既定値使用と、実際の作業先が書込不可・容量不足の場合を区別し、後者では自動で他の場所へ切り替えない。
- 設定の独立保存、ボード本文確定、ディスク保存成功は別の境界であり、設定成功だけでボードを保存済みと表示しない。

### 共通受入条件

| ケース | 前提 | 操作・事象 | 期待結果 |
| --- | --- | --- | --- |
| 正常 | 未保存の本文・配置・枠・表示がある | グリッド表示・間隔・スナップ・回転刻みを変更し設定だけ保存する | 即時適用・設定だけ独立保存し、再開で設定は復元する。ボード未保存部分は混入しない |
| 異常 | プロジェクト設定保存が失敗 | 設定画面を閉じて再試行する | 適用値は保持し未保存と再試行を表示する。成功後は再開・別PCでも保持 |
| 正常 | 現ボードが利用中 | PC設定を保存し次の新規作成・オープン・再オープンを行う | 現ボードは旧値、次回は成功値。同じWindows利用者共通で別PCはそのPCの設定を使う |
| 異常 | PC設定の書込みが失敗 | 値を変更して再試行する | 旧保存値を使用し入力値・再試行を残す。再試行成功後の次回から新値を使う |
| 異常 | 起動時にPC設定を読めない | 起動する | 失敗を通知し履歴100・プロジェクト隣の作業先など通常既定値で開始する |
| 異常 | 適用された実作業先が書込不可・容量不足 | 作業を開始する | 理由を通知し自動代替せず、既存正常内容と編集を保持する |

## フォント差による再開調整の共通ルール

REQ-011・019に適用する。PC標準フォント使用と上限補正時の無通知はユーザーの決定。補正単位・原本分離・履歴の扱い・補正不能候補の拒否は[DES-009](../product-design/project-persistence.md#フォント差読込と保存原本)の具体化を反映する。

- 本文・幅・文字サイズを保持して新PCの標準フォントで全文高を再計算する。グループ枠は必要時だけ拡大し、自動縮小しない。枠拡大だけなら通知し、保存前は未保存変更として扱う。
- フォント差で外周が配置範囲を超える場合は、超過軸の座標を必要最小限だけ補正する。未所属メモはそのメモ、所属メモは保持枠と全所属要素を一体で移動して相対配置を保つ。本文・幅・文字サイズを変更せず、スナップもしない。座標補正した対象の調整通知は出さず、他の保存・読込失敗通知は抑止しない。
- 表示中心・倍率は調整と連動して補正しない。調整前の読込内容を最後の保存成功内容として保持し、枠・座標が変わった表示状態は別の未保存状態とする。高さだけの再計算で保存属性が同じなら未保存にしない。設定だけの保存へ調整を混入させず、ボード保存成功後に調整済み内容を新保存基準とする。
- 読込時の環境調整をボードUndoへ入れない。履歴は空で開始し、次の利用者操作のUndo基点は調整後状態。調整後の終了・切替は未保存保護を適用する。
- 本文・幅・文字サイズと相対配置を維持した座標補正でも収まらない候補は、読込を拒否して理由を通知し旧ボード・元ファイルを保持する。内容切捨て・文字縮小や元ファイルの自動修復をしない。

### 共通受入条件

| ケース | 前提 | 操作・事象 | 期待結果 |
| --- | --- | --- | --- |
| 正常 | 別PCでメモ高さが増え保持枠に収まらないが配置範囲内 | 再開する | 本文・幅・文字サイズを保ち必要枠拡大を通知・未保存とする。高さ減少では枠を縮めない |
| 正常 | フォント差で未所属メモまたはグループ外周が範囲を超えるが補正可能 | 再開する | 必要最小限移動しグループ相対配置を保つ。対象の調整通知なし、枠・座標は未保存、保存表示位置は無補正 |
| 正常 | 未保存のフォント差枠拡大・座標補正がある | 設定だけ保存しボード変更を破棄、またはボード保存して再開する | 設定だけなら原本の枠・座標を保持。ボード保存成功後は調整後内容を復元する |
| 正常 | フォント差で高さだけ変わり保存属性は同じ | 再開し次の利用者編集をUndoする | 高さ差だけで未保存にせず環境調整の履歴を作らない。Undoは利用者編集前の調整後状態へ戻す |
| 異常 | 位置補正だけでは全文・枠を配置範囲へ収められない | 開く | 読込を拒否して理由を通知し、本文切捨てや元の修復をせず旧ボードと元ファイルを保持する |

## 同一ファイル利用と保存再試行の共通ルール

REQ-011～017・019に適用する。二重オープン拒否・置換後失敗の明示再試行・外部変更時の別名保存はユーザーの決定。同一実体判定・ロック寿命と照合の結果は[DES-009](../product-design/project-persistence.md#同一ファイルの排他契約)の具体化に基づく。API・内部番号や記録構造は設計に保持する。

- 同じPCの本アプリ別プロセスで同一ファイルを二重オープンしない。別ファイルは同時利用可能。パス別名・ハードリンクでも同一実体なら使用中を通知して拒否し、現在ボード・ファイルを保持する。排他を確認できない場合も開かず理由を示す。同一セッション再オープンは所有を維持して既存の未保存保護と最新内容再読込を行う。
- 開いてからプロジェクトを閉じるまで所有し、保存のファイル置換中にも隙間を作らない。別名保存は新保存先の所有を確保し、成功後に切替・旧先解放、失敗時は旧先と編集を維持する。異常終了後の再開は再度所有できることと保存途中の内容を確認し、単なる使用中記録の残存で永久拒否しない。外部アプリ・別PCの書換え防止保証は追加しない。
- 本ファイル置換後に保存成功となる前に失敗した場合は、その保存先への設定・定期・手動の追加書込を止める。現在編集を保持して編集継続でき、利用者の明示再試行で中断処理の記録と新旧ファイルを照合する。一致した中断処理を完了してから後続保存へ進む。
- 中断処理の完了はその保存に含まれた内容だけを保存済みにする。追加入力や設定を巻き戻さず、後続変更を未保存として維持し、その後の保存で扱う。後着の中断完了を失敗した操作の二重成功通知や、取消済み終了・切替の実行に使わない。
- 照合不一致・外部変更・削除では元保存先へ上書きしない。現在編集を保持して別名保存できる。外部変更版を再読込する場合はREQ-019の保存・破棄・キャンセルと候補検証を適用する。再試行中の追加障害でも書込を停止し、編集・既存正常内容・復旧候補を保持する。

### 共通受入条件

| ケース | 前提 | 操作・事象 | 期待結果 |
| --- | --- | --- | --- |
| 異常 | 同一ファイルを別プロセスで使用中 | 元パス・別名パス・ハードリンクから開く | 使用中として拒否し、両プロセスの内容と元ファイルを保持する |
| 正常 | あるファイルを使用中 | 別プロセスで異なるファイルを開く | 別ファイルの利用を認める。保存の置換で同一ファイルの二重利用を許さない |
| 正常 | 同一セッションでファイルを利用中 | 未保存保護を経て再オープンする | 排他を維持して最新内容を再検証し、誤って別プロセスの二重オープンとして拒否しない |
| 異常 | 使用プロセスが異常終了した | 再度ファイルを開く | 所有と中断内容を再確認し、最後の成功内容を保護して再開できる。未完了内容を自動成功扱いしない |
| 正常 | 元ファイルを所有している | 別名保存が成功／失敗する | 成功で新保存先へ切替・旧先解放。失敗では元保存先・編集を維持する |
| 異常 | 置換後に保存成功前の失敗が発生 | 追加入力し、定期・設定・手動保存を要求する | 編集は保持・継続できるが追加書込は停止。失敗と明示再試行を示す |
| 異常 | 中断処理の記録・新旧ファイルが一致し、後続変更がある | 明示再試行する | 中断処理を完了しその内容だけ保存済み。後続編集を未保存で保持して後続保存へ進み、巻き戻さない |
| 異常 | 記録不一致・外部変更・元削除のいずれか | 再試行または別名保存する | 元への上書きなし、理由を示し現在編集を別名保存できる。外部版再読込は未保存保護を経る |
| 異常 | 明示再試行中に再度障害 | 再試行する | 書込停止・編集と正常内容保護を維持し、成功と誤表示しない |

## 性能の共通評価条件

REQ-021〜026は次の合意された条件で評価する。閾値はユーザーが採用した初期受入基準であり実測結果ではない。各指標を3回測定し、全回が基準内であることを確認する。

- 評価PC：Core i5-1235U、メモリ16GB、内蔵GPU、SSD、フルHDノート、Windows 11。
- テスト画像：全500枚、全数1920×1080。JPEG350枚、PNG100枚、WebP20枚、GIF10枚、TIFF10枚、BMP10枚。
- 500枚は初期評価条件であり登録上限ではない。これを超える画像規模の同一性能保証はしない。
- 通常時：操作反応100ms以内、ズーム停止後の細部表示1秒以内。自動保存中・手動保存中は500ms以内・2秒以内に緩和し、いずれも操作を継続できることとする。再開5秒以内・初回取込30秒以内は維持する。
- 評価画像群：写真・イラスト相当の内容を含む固定画像群を使い、単色ダミーや同一画像の大量複製を避ける。同じ画像群で繰り返し測定する。
- 細部表示完了：ズーム対象画像の表示範囲に一時的な低解像度表示・未描画部分が残らず、その倍率での最終的な精細さになった状態。画面内の全画像の完了は求めない。
- 試行の開始条件：再開・初回取込は各試行前にアプリを再起動する。パン・ズームは評価ボードの読込完了後に測定する。OS再起動・キャッシュ消去は必須にしない。再開は開く操作、初回取込はファイルを渡す時点から計測し、アプリ再起動そのものの時間は含めない。
- 根拠・出典：未決事項インタビューにおけるユーザーの回答。手動保存中の基準、画像群の方針、細部表示完了の意味、各試行の開始条件への合意。実測結果ではない。
- 未決事項（スキップ）：以下は未解決のまま引き継ぎ、確定するまで性能要件の完全な受入判定を保留する。

| 未決内容 | 引継ぎ先・確定時期 |
| --- | --- |
| テスト画像の実ファイル・総容量・一覧・形式・寸法・識別情報の固定 | 検証担当が検証準備時に確定する。上記の枚数・形式内訳・寸法・代表性を満たすこと |
| ボードの固定状態（配置・回転・拡縮、画像・メモを含むグループ数、メモ数・文章量） | 実利用・試作を確認し、検証計画時に確定する |
| 具体的な操作対象・入力手順 | 設計・検証担当が検証計画時に確定する |
| 計測方法、保存処理中の検出、対象画像の細部表示完了の具体的判定手順 | 設計・検証担当が検証実施前に確定する。自動・手動保存との重なりをそれぞれ確認する |

スキップは解決済みを意味しない。性能要件は条件付き合意とし、未決条件の解消・合意前の最終的な受入判定は行わず、ユーザーの有用性や制作品質向上という成果評価とプロダクト受入条件を区別する。

## REQ-011：保存内容の復元

- 種類：機能
- 参照要求：[DEM-004](../product-demands/cross-cutting.md#dem-004蓄積内容を保ち後日再開する)
- 参照時点の要求：DEM-004「画像・配置・グループ・メモを保ち後日再開する」。参照要求はいずれも合意済み。
- 内容：画像・配置・グループ・独立メモに加え、プロジェクト設定と表示中心・倍率を保存し、後日再開時に復元できる。配置には画像の位置・回転・表示サイズを含める。
- 適用条件：利用者のWindows 11初期版での単一ボードの利用。
