# 作成・更新・移行

1. バンドルルート、正本、対象文書、版、追加条件、書き込み範囲を確認する。対象の既存規則がなければ、通常文書は`type`を必須とし、`title`と`description`を推奨する。保存先・種別・業務ID・承認状態は固定しない。
2. 新規作成は一つの知識単位を一文書にする。テーマ文書を一つの単位として扱える。既存文書を移行する際は、分割・移動を別途求められていなければ現在の単位を維持する。
3. frontmatterをファイル先頭に置く。既存のYAMLと未知キーを保持し、必要箇所だけ編集する。テンプレートの先頭コメントより前に配置する。本文の見出し・業務ID・数値・状態・根拠を形式変換のために変更しない。
4. `title`は文書の表示名、`description`は内容を見つけるための一文とする。本文の暫定事項を確定事項として要約しない。任意の出典・検証・日時は根拠がある場合だけ記録する。
5. 索引がある場合は、変更対象の説明付きリンクを更新する。索引本文に業務上の一覧・対応表があれば保持する。全体索引の更新権限がなければ必要な変更を呼び出し元へ返す。
6. [検査](validation.md)を実行し、移行では変更前後の本文・ID・アンカー・既存メタデータを比較する。形式検査の成功を内容の承認として記録しない。

新しいバンドルに索引を作る場合の最小例：

```markdown
---
okf_version: "0.2"
---
# ナレッジ

- [運用手順](operations.md) - 日常運用と復旧の手順。
```

通常文書の例（種別と項目の追加は呼び出し元で選ぶ）：

```markdown
---
type: Playbook
title: 運用手順
description: 日常運用と復旧の手順を説明する。
---
# 運用手順

本文をここに記載する。
```

この例を固定テンプレートとして全プロジェクトに強制しない。既存バンドルへメタデータだけ追加する場合、版宣言以外の任意項目・履歴ファイル・新しい承認フローは追加しない。
