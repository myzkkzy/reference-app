# データ構造の設計

共通原則と権限は[スキルの入口](../SKILL.md)に従う。

## 入力と出力

- 入力：要件、対象機能、要件本文の定義、データ所有、既存構造。
- 出力：関連図、項目定義、制約・更新ルール、必要な保存・変換契約。

## 手順

- 関連図、項目定義表、制約・更新ルールを組み合わせる。
- 意味、型、必須・任意、初期値、範囲、単位、ID、参照、多重度を定める。
- 不変条件、参照不整合、作成・更新・削除の責務、保持・破棄・復元を扱う。
- 整合性を守る更新単位、所有・参照・同時更新時の制御を示す。
- 永続・一時・再生成データを区別し、正本と変換を示す。
- 永続化時は形式・バージョン、読込検証、非対応形式、非破壊の移行を定める。
- 入力検証・資源制御、既存データと編集中状態の保護を要件から具体化する。
- 失敗時の再試行と回復の保証範囲を、要件に基づいて定める。
- データ構造を共通化する場合は適用範囲・責務・変更影響を確認し、必要な変換契約を定める。
- Undoは要件にある場合に扱う。モデルをクラスやDB表と機械的に一致させない。

## 確認例

- 入力：ファイル保存でありDB採用は指定されていない。
- 期待：必要な保存契約と関連構造を設計し、DBやUndoを自動採用しない。
