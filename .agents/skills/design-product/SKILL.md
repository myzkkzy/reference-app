# プロダクトの設計

## 目的と責務

要求・要件、受入条件、現行構成を入力とし、指定された範囲の設計を具体化する。

## 共通原則

依頼と呼び出し元の権限を守り、指定された操作だけを行う。
適用規則は入力または既存設定から確認し、重要な不足だけ質問する。
保存先・ID体系・担当名を固定せず、対象の規則と既存成果物に合わせる。
参照資料を読むだけで、依頼範囲や更新権限を広げない。

- 全体構成・機能・データ・テスト方針は必要なものだけ扱う。全操作の実施は必須ではない。
- 上流の目的・振る舞い・業務ルール・受入条件を変える判断は、管理担当へ返す。
- 試作・実装・具体的な試験計画と実行は別担当へ引き継ぐ。
- 設計の状態・完了を判断する場合は[設計レビュー](references/design-review.md)を読む。
- 設計完了、要件合意、ADR採用、試験合格を区別する。

## 操作の選択

文書の保存時は、適用規則が指定する形式スキルと追加条件を使う。OKFが指定された場合は[manage-okf](../manage-okf/SKILL.md)でメタデータ・索引・形式検査を扱い、内容は本スキルで作成する。指定がなければOKFを強制しない。

依頼に該当する手順だけを読む。表の全操作を順に実行する必要はない。

| 必要な作業 | 参照する手順 |
| --- | --- |
| 全体構成の設計 | [全体構成の設計](references/architecture.md) |
| 機能・責務の設計 | [機能・責務の設計](references/component.md) |
| データ構造の設計 | [データ構造の設計](references/data-model.md) |
| テスト方針の策定 | [テスト方針の策定](references/test-strategy.md) |

## テンプレート

各手順から、対象の成果物に必要なテンプレートだけを参照する。
テンプレートは項目の記載枠である。状態・ID・パスは適用規則に合わせる。
複製先でプレースホルダーと例示行を置換し、不要な節を削除する。
テンプレート自体を成果物として編集しない。
