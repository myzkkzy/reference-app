# テスト設計レビュー

共通原則と権限は[スキルの入口](../SKILL.md)に従う。

## 入力と出力

- 入力：操作と対象範囲、方針・条件・ケース、受入条件・設計契約の根拠、未決・依存と現行状態。
- 出力：確認済み／未確認、対応漏れ・矛盾・修正対象、引継ぎ可能な範囲・残件・再確認範囲。

## 確認する事項

- 共通戦略とテーマ別戦略の責務、継承する原則・対象境界が整合し、矛盾は共通戦略へ返されている。テーマ別戦略と配下設計、設計と適用戦略が相互に参照できる。
- 重要な戦略判断→COND群・共通仕様→CASEの対応を本文の意味まで確認する。リンクの存在だけを網羅の証拠にせず、未決・適用外の理由、条件抽出の選定理由、要件・製品設計への直接の期待結果根拠が維持されている。
- 対象・対象外と理由、根拠本文・見出し・対象条件、確認時点・状態・許可範囲が明確。要約だけで判定せず正本と照合する。
- 方針は検証目的、層と種別・品質観点、分担理由、観測・制御境界、証拠と未決が明確。不要な層・観点を一律に要求しない。
- 分析は対象条件への対応、技法・網羅対象・優先理由が追跡可能。未対応・対象外・延期・未決を区別し、根拠のない網羅率で完成判断しない。
- ケースは根拠→条件→ケースの対応、入力・前提・環境・準備・操作・後片付け、観測可能な期待結果と根拠が揃う。共通データ・契約と矛盾せず、同じ目的の機械的な重複を残さない。
- 期待結果・閾値・負荷・試行回数・保証は上流と整合。技術契約を製品受入へ置き換えず、実装の挙動を正解と推定しない。
- ID・見出し・リンク、参照方向・分類・索引、共通定義の正本が適用規則と整合。既存REQへ条件IDや逆向き参照を追加しない。
- 判定を左右する未決と仕様確定済みの後続準備を区別。未決依存の範囲を確定・引継ぎ可能にせず、独立部分を続ける。

## 完了判断と差戻し

- 依頼した操作と成果物種別に応じた条件を適用する。方針だけにケース完成、分析だけに実行準備、テスト設計に構成図・通信項目の再定義を要求しない。
- 方針・分析の具体化範囲と、ケースまで揃った文書設計の完成範囲を分けて報告する。状態は適用規則に従い、新しい状態・台帳を作らない。
- 根拠・対応・再現方法・判定方法が揃い、判定を左右する未決が解消した範囲を引継ぎ可能とする。実データ・環境・コードの未作成、試験未実施だけでは文書設計の完成を妨げない。
- 実行準備完了・要件合意・ADR採用・製品試験合格は別。全ケース完成を全製品設計の共通条件にしない。
- ケース・手順の不足はテスト設計、条件・分担の不足は分析・方針へ返す。契約矛盾・観測不足は製品設計へ、振る舞い・品質基準の不足は要件担当へ返す。
- 意味への影響がある範囲だけ再レビューする。誤字・リンク修正で状態を戻さず、評価待ち・保留の解消後は適用規則に従う。
