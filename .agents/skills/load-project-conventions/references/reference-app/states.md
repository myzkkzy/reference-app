# 状態と遷移

## 着想

- 新規案は検討中とする。
- 本人の選択により引継ぎ候補・保留・見送りへ更新し、判断理由を残す。
- 引継ぎ候補は有望案として選び、要求定義へ進めたい案である。
- 保留は材料不足または今は取り組まない案、見送りは理由を持って進めない案である。
- AIの推奨だけでは状態を変えない。保留・見送りも要約と理由を削除しない。
- 再検討時は以前の判断と変更理由を残す。
- 要求定義へ移行しても引継ぎ候補を維持し、構想に引継ぎ先と経緯を追記する。

## 要求

- 優先度は必須・重要・将来候補・未決とし、理由を添える。
- 合意状況はドラフト・合意済み・保留・廃止とする。
- 合意済みは対象内容への明示的な合意がある場合だけ使用する。
- 意味が変わる編集はドラフトに戻す。現在の理由・根拠を更新する。
- 未決の数値や回答を捏造せず、未決事項・仮定に記録する。

## 要件

- 優先度は必須・重要・将来候補・未決とする。要求から自動確定しない。
- 合意はREQ単位で管理し、実装完了・試験合格と区別する。

| 遷移 | 条件 |
| --- | --- |
| 新規 → ドラフト | 要件案の作成 |
| ドラフト → 合意済み | 本文・受入条件・優先度への明示的合意。重大な未決がなく受入条件が検証可能 |
| ドラフト → 条件付き合意 | 確定部分、残る条件、引継ぎ先、確定時期、解消条件、進行範囲への明示的合意 |
| 条件付き合意 → 合意済み | 条件の解消と確定内容への明示的合意 |
| ドラフト・条件付き合意・合意済み → 保留 | 根拠要求の矛盾・不足等で判断不能 |
| 保留 → ドラフト | 理由が解消して再確認可能 |
| 条件付き合意・合意済み → ドラフト | 意味・適用範囲・受入条件の変更 |
| 廃止以外 → 廃止 | 適用終了の明示的決定 |

- 元要求の不足・矛盾・未合意に依存する部分は保留し、独立部分はドラフト化する。
- 期待結果と選定方針が確定し、方式や具体的試験操作だけが残る場合は合意済みにできる。
- 範囲・合否を左右する条件が残る場合は条件付き合意とする。
- 要求の矛盾や不足で判断不能なら保留とする。
- 条件付き合意では合意範囲の設計・試作を進め、最終受入は条件の確定と合意後に行う。
- 個別回答、スキップ、計画採用・文書反映の指示だけで全体の合意を推定しない。
- 対象範囲への明示的合意が既にあれば、確認を重ねない。
- 「根拠・出典」に現在の合意日・合意者・範囲・回答根拠を記載する。
- 「未決事項」に残る条件・影響・担当・確定時期・解消条件・進行範囲を記載する。
- 本文、文脈、引継ぎを同期する。要件化状況は別に管理する。
- 誤字・リンク修正や、影響しない要件の状態は戻さない。
- 機能の受入条件は「正常」「異常」のみで分類する。
- 正常は認められた利用が成立する場合、異常は入力不備・処理失敗への対応である。
- 境界値・権限不足は前提や期待結果に記載し、異常からの回復は異常に分類する。

## 設計

- 新規・見直し中はドラフト、試作・検証・必要な合意待ちは評価待ちとする。
- 入力不足・矛盾で判断不能なら保留、適用終了なら廃止とする。
- 評価待ち・保留の解消後はドラフトとして再確認する。
- 意味への影響があるDESだけドラフトへ戻す。誤字・リンク修正では戻さない。
- 実装引継ぎ可能は、設計レビューの完了条件を満たした範囲だけに使用する。
- 局所的なコード構成は残せる。方式の根拠に必要とした試作結果は確認する。
- 設計完了を本人合意・ADR採用・試験合格と同一視しない。
