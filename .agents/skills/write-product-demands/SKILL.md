# 要求の記述

## 入力と出力

- 入力：対象者、状況、課題、代替手段、期待成果、根拠、既存要求、適用規則。
- 出力：要求本文、未決事項、指定された機能・制約の引継ぎ情報。

## 適用範囲

依頼と呼び出し元の権限を守り、指定された操作だけを行う。
適用規則は入力または既存設定から確認し、重要な不足だけ質問する。
保存先・ID体系・担当名を固定せず、明示された規則と既存成果物に合わせる。
独立した別操作が必要なら結果を引き継ぐ。別スキルの参照だけで作業を拡張しない。

## 手順

文書の保存時は、適用規則が指定する形式スキルと追加条件を使う。OKFが指定された場合は[manage-okf](../manage-okf/SKILL.md)でメタデータ・索引・形式検査を扱い、内容は本スキルで作成する。指定がなければOKFを強制しない。

- 目的、対象者、利用状況、課題、代替手段、期待成果を整理する。
- 対象範囲・対象外、優先度と理由、成功指標、根拠を記載する。
- 成功指標は事業・ユーザーの成果とする。未指定の数値を補わない。
- 機能・方式・数値制約の指定は内容と出典を保持し、背景の要求を確認する。
- 指定内容は要件候補として引継ぎ節へ分け、合意済み要件へ昇格させない。
- 事実・意向・提案・仮定・未決を区別し、要求本文の管理元を一つにする。
- 実在する課題・成果に沿ったテーマで整理し、構想の仮説を合意済み要求に転記しない。
- 未回答事項を残して独立部分をドラフト化する。受入条件や実装は作成しない。

## 参照資料

- 対応する成果物を作る場合：[テンプレート topic.md](assets/templates/topic.md)。
- 対応する成果物を作る場合：[テンプレート cross-cutting.md](assets/templates/cross-cutting.md)。

テンプレートは項目の記載枠である。状態・ID・パスは適用規則に合わせる。
複製先でプレースホルダーと例示行を置換し、不要な節を削除する。
テンプレート自体を成果物として編集しない。

## 確認例

- 入力：具体的な機能だけを指定される。
- 期待：内容と出典を保持し、背景の要求を確認して要件候補を分離する。
