# 受入条件の作成

共通原則と権限は[スキルの入口](../SKILL.md)に従う。

## 入力と出力

- 入力：対象要件、業務ルール、評価基準、制約、既存の受入条件。
- 出力：機能・非機能・制約に対応する受入条件と未決の評価条件。

## 手順

- 機能はケース、前提、操作・事象、期待結果を記載する。
- 正常・異常の区分は適用規則に従い、境界値・権限不足・回復も検討する。
- 非機能は評価条件、基準、検証方法を記載する。
- 制約は遵守を判定する条件と確認方法を記載する。
- 閾値、負荷、測定条件、業務判断を捏造しない。
- 成功指標や具体的なテスト手順と区別し、要件の範囲を無断で広げない。
- 条件の追加・変更が要件の意味に影響する場合は、その影響を返す。
- 作成だけで合意済み・試験合格としない。

## 参照資料

- 受入条件を記述する場合：[挿入用テンプレート](../assets/templates/acceptance-criteria.md)。
- 分類名は適用規則に合わせ、不要な表を削除して対象要件の本文へ挿入する。

## 確認例

- 入力：性能の閾値と測定条件が未指定である。
- 期待：不足を未決として返し、任意の数値で検証可能・合意済みにしない。
