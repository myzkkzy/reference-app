# 要件と受入条件の具体化

## 目的と責務

実在する要求と適用規則を入力とし、要件本文または受入条件を作成・更新する。

## 共通原則

依頼と呼び出し元の権限を守り、指定された操作だけを行う。
適用規則は入力または既存設定から確認し、重要な不足だけ質問する。
保存先・ID体系・担当名を固定せず、対象の規則と既存成果物に合わせる。
参照資料を読むだけで、依頼範囲や更新権限を広げない。

- 要求がない場合は不足を返す。架空の要求を補わず、新しい要求は管理担当へ返す。
- 要件全体の依頼では本文と受入条件を扱う。本文だけ・条件だけの依頼も受け付ける。
- 受入条件だけの依頼では、要件の意味を変える内容を確定せず、影響を返す。
- 要求への合意、要件への合意、試験合格を区別する。設計や試験実行は行わない。

- 用語の意味、操作の流れ、業務ルールは必要な範囲を要件本文に記載する。共通説明は管理元を参照する。

## 操作の選択

文書の保存時は、適用規則が指定する形式スキルと追加条件を使う。OKFが指定された場合は[manage-okf](../manage-okf/SKILL.md)でメタデータ・索引・形式検査を扱い、内容は本スキルで作成する。指定がなければOKFを強制しない。

依頼に該当する手順だけを読む。表の全操作を順に実行する必要はない。

| 必要な作業 | 参照する手順 |
| --- | --- |
| 要件本文の具体化 | [要件本文の具体化](references/requirements.md) |
| 受入条件の作成 | [受入条件の作成](references/acceptance-criteria.md) |

## テンプレート

各手順から、対象の成果物に必要なテンプレートだけを参照する。
テンプレートは項目の記載枠である。状態・ID・パスは適用規則に合わせる。
複製先でプレースホルダーと例示行を置換し、不要な節を削除する。
テンプレート自体を成果物として編集しない。
