# 画面遷移図

- 画面・ダイアログの表現には適切なMockupプリセットを使う。接続線・矢印・条件ラベルはGeneralで構成し、存在しないUI部品を遷移説明のために追加しない。
- 画面、ダイアログ、同一画面内の表示状態を名称または形で区別する。状態の変化をすべて新画面とみなさない。
- コネクターは遷移方向を明示し、操作・発火条件と、分岐に必要な条件を短く記す。戻り・取消・失敗時の行き先も、根拠がある範囲で示す。
- 操作別の部分図に分けてもよい。同じ画面を再掲するときは「同一画面の再掲」と明記し、新画面と誤認させない。部分図ごとに入口、成功、取消、失敗の到達先を追えるようにする。
- 直交線を基本とし、接続辺・経由点を指定して各線に経路を割り当てる。線同士の交差や共有区間、無関係なノード上の通過、条件ラベル・矢印の重なりを避ける。線のジャンプ表示だけで交差を処理しない。
- 出力画像を全体と拡大の両方で確認し、配線と文字を目視で点検する。構造検査だけで配線を確認済みとしない。
- 既存の要件・画面設計にない遷移を確定事項として追加しない。案と未決は図中で区別し、本文の未決事項へつなぐ。
- 画面名や条件は画面設計本文と揃える。複雑な業務ルールや受入条件の正本は要件本文を参照する。
