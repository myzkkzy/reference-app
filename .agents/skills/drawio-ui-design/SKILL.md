# draw.ioによる画面設計図

## 文書の表記

- 回答・意向・合意の主体は「ユーザー」、製品の操作・利用条件の主体は「利用者」と記載する。
- 通常の説明文には日付を記載しない。ファイル名・リンク先・メタ情報・明示的な日付項目や日付列、日付形式の仕様・コード例・テストデータは例外とする。

## 対象と責務

画面設計の内容は依頼元の要件・設計担当が決める。本スキルは画面遷移図と画面構成図を編集可能な`.drawio.svg`として描き、検査する。要件や未決事項を図だけで確定しない。必要な図だけ作る。

## 作業

検証・描画・保守用テストの実行直前に、[依存準備](references/editing-and-rendering.md#実行直前の依存準備)に従って`scripts/.venv`と`scripts/node_modules`の依存を確認する。環境がなければ作成し、不足・版の不一致があれば導入する。Pythonは常に専用仮想環境の絶対パスを使う。探索・読解だけでは導入しない。

1. 対象の要件、画面設計、全体図、既存の`.drawio.svg`を読む。画面・操作・状態の出典と未決事項を整理する。
2. 遷移図は[遷移図の規約](references/screen-transition-rules.md)、画面構成図は[ワイヤーフレームの規約](references/screen-layout-rules.md)に従う。draw.ioの図形・テキスト・コネクターで構成し、図全体を単一画像にしない。
3. 画面・ダイアログ・UI部品は `Mockup ***` の実在するプリセットを優先する。[プリセット選択](references/mockup-presets.md)を参照し、必要な表現がない部分だけGeneralの図形を組み合わせる。既知の部品が描画できない場合は処理の不具合として停止し、黙ってGeneralへ置換しない。
4. `.drawio.svg`を正本として、編集データの読込み・更新・描画をメモリ上で行う。[編集・描画手順](references/editing-and-rendering.md)のPython APIを使い、変更しない要素のID・接続関係を維持する。独立したXML・drawio・作業用SVGを作らない。SVGの表示部分だけを編集せず、同じ図データから表示と埋込みデータを生成する。
5. 専用仮想環境のPythonで`scripts/drawio_svg.py validate <出力.drawio.svg>`を実行して構造を検査し、出力画像を全体と拡大の両方で確認する。ワイヤーフレームの配置・部品・日本語・文字切れと、遷移図の線の交差・重複・ノード通過・矢印・条件ラベルを確認する。構造検査は表示品質を保証しない。検査失敗時は既存出力を保持する。
6. 対応するMarkdownから`![画面遷移図](diagrams/topic-transition.drawio.svg)`のように相対パスで埋め込む。名前・配置は対象プロジェクトの規則を優先する。画面設計本文をIDと英語の内容名を組み合わせたファイルへ移動した場合も、図の配置はその規則に従い、埋込リンクを参照元から解決できるよう更新する。

正式成果物は1ファイル1ページの`.drawio.svg`で、ドキュメントからもSVGを参照する。表示検証用PNGの一時作成は許可するが、ドキュメントから参照せず、成果物として保存したりGitへ追加したりしない。PNGは作業専用の一時ディレクトリへ保存し、検証の成功・失敗にかかわらず終了時に今回作成した画像を削除する。削除できない場合は残存パスを報告する。

ローカルのdraw.io描画資源とヘッドレスブラウザーを使い、Desktop版draw.ioは起動しない。図データの一時ファイルは、検証済みの完成SVGを安全に置換するための保存用ファイル1個だけ許容する。この制約は表示検証用PNGと区別する。描画失敗・タイムアウトでは既存出力を保持し、自動再試行やDesktop CLIへの切替は行わない。

サンプルは[画面遷移図](assets/sample-transition.drawio.svg)と[画面構成図](assets/sample-layout.drawio.svg)。生成元は`scripts/sample_diagrams.py`で、部品の形状・親子関係をメモリ上のモデルとして確認できる。既存の設計図の一括置換は行わず、編集を依頼された範囲へ適用する。

構造検査は表示品質を保証しない。レンダリングや再読込を確認できないときは、その範囲を未確認として伝える。
