本文は1項目1ファイルで保存する。要件は機能・非機能の種別と領域の階層に置く。例：`docs/product-requirements/functional-requirements/comparison/REQ-004-board-overview-and-detail.md`。設計は構成・データ・画面・インターフェース・機能・非機能に分け、機能・非機能設計には領域階層を設ける。各工程の `index.md` に全ID一覧と上流対応表、種別・領域の `index.md` に下位索引・本文への案内を置く。保存先と分類・IDの規則は[文書規則](.agents/skills/load-project-conventions/references/reference-app/documents.md)を参照する。
